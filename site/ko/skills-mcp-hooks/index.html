Claude Code와 Codex가 불러오는 스킬, MCP 서버, hook 확인하고 끄기

회사 계정으로 Claude Code(클로드 코드)를 쓰다가 claude mcp add로 GitHub MCP 서버를 추가했습니다. 그런데 일주일 뒤 같은 저장소를 개인 계정으로 열어 보니 그 서버가 없어요.

2026년 10월 15일 업데이트

그 서버는 회사 계정의 .claude.json에만 들어 있기 때문입니다. 계정마다 무엇을 불러오는지 알려면 이 파일을 계정 수만큼 열어 봐야 합니다. 프로젝트 설정과 플러그인도 따로 봐야 하고요.

스킬도 사정이 비슷합니다. Codex에서도 쓰려고 ~/.agents/skills에 복사해 두면 같은 스킬이 두 벌이 됩니다. 넉 달째 안 쓴 스킬도 모든 프로젝트에서 그대로 불러옵니다.

clausona 대시보드의 Extensions 화면을 열면 이걸 한 목록으로 볼 수 있습니다. 프로젝트를 하나 고르면, 그 프로젝트에서 Claude Code와 Codex가 불러오는 스킬, MCP 서버, hook을 계정별로 보여 줍니다.

같은 목록에서 바로 끌 수도 있어요. 이 프로젝트에서만 끌지 모든 프로젝트에서 끌지 고를 수 있고, 안 쓰는 건 지워도 됩니다. 파일을 바꾸기 전에는 항상 백업해 두기 때문에, u를 누르면 마지막 변경이 되돌아갑니다.

clausona

# github 서버가 어느 계정에 있는지, 이 프로젝트에서 켜져 있는지
clausona mcp show github

# 90일 동안 안 쓴 Claude 스킬
clausona skills ls --scope unused --tool claude

이 프로젝트에서 불러오는 것

clausona를 실행하고 Extensions를 고르면 돼요. 기준이 되는 프로젝트는 지금 있는 폴더가 속한 git 저장소입니다. 저장소 밖이라면 그 폴더 자체가 기준이에요.

왼쪽 첫 줄이 그 프로젝트이고, 옆에 거기서 불러오는 항목 수가 나옵니다. 오른쪽 표는 이 항목들을 어디서 왔는지에 따라 묶어 보여 줍니다. 프로젝트에 있는 것이 먼저 나오고, 나머지는 왼쪽 목록 순서대로 나옵니다.

Claude와 Codex는 탭으로 나뉘어 있고, tab으로 오갑니다. 스킬, MCP 서버, hook은 1, 2, 3으로 바꿉니다.

첫 줄 아래에는 출처마다 줄이 하나씩 있습니다. 이 줄을 열면 불러오지 않는 것까지 보여요. 이름이 같은 다른 스킬에 가려진 스킬이나, 이 프로젝트에서 꺼 둔 스킬 같은 것들입니다.

행에서 enter를 누르면 자세한 내용이 열립니다. 파일 위치와 계정별 상태가 나오고, 스킬이라면 몇 번 썼는지도 나와요.

다른 프로젝트를 보려면 p를 누르세요. Claude Code나 Codex가 어느 계정에서든 기록해 둔 폴더가 목록으로 나오고, 글자를 치면 목록이 좁혀집니다.

계정마다 어떤 MCP 서버를 띄우는지

계정끼리 가장 많이 달라지는 게 MCP 서버입니다.

플러그인은 계정끼리 공유되니, 플러그인에 딸린 서버는 어느 계정에나 있습니다. 반면 claude mcp add로 추가한 서버는 그 계정의 .claude.json에만 들어가서 그 계정에서만 뜹니다.

Claude 탭의 MCP 화면에서 m을 누르면 표가 열립니다. 행은 서버, 열은 계정이고 Codex 열도 하나 있어요. 칸마다 그 서버가 이 프로젝트에서 그 계정으로 뜨는지 표시됩니다.

칸에서 space를 누르면 그 계정의 서버만 이 프로젝트에서 끄거나 켭니다. 다른 계정은 그대로예요.

다만 프로젝트의 .mcp.json에 있는 서버는 예외입니다. Claude Code가 프로젝트 단위로 켜고 끄기 때문에, 이 칸을 바꾸면 모든 계정에 한꺼번에 적용됩니다.

명령줄에서는 이렇게 확인합니다.

clausona mcp show github

이 서버가 어느 계정에 있는지, 이 프로젝트에서 켜져 있는지 알려 줍니다. 설정에 든 비밀 값은 보여 주지 않습니다.

이 프로젝트에서만, 또는 모든 프로젝트에서 끄기

행을 골라 space를 누르면 이 프로젝트에서만 꺼집니다. g는 모든 프로젝트에서 끕니다.

바꾸기 전에 확인 창이 먼저 뜹니다. 파일마다 무엇이 바뀌는지 한 줄씩 보여 주고, 백업을 어디에 두는지도 알려 줘요. y를 누르면 적용하고, n을 누르면 아무것도 바뀌지 않습니다.

clausona는 Claude Code와 Codex가 원래 읽는 설정에 적습니다.

Claude 스킬을 이 프로젝트에서 끄면 프로젝트의 .claude/settings.local.json에 있는 skillOverrides에 그 스킬을 "off"로 적습니다. 계정의 .claude.json에 있는 Claude MCP 서버나 플러그인에 딸린 서버를 이 프로젝트에서 끄면, 그 계정 .claude.json의 프로젝트 항목에 있는 disabledMcpServers에 이름을 넣습니다. /mcp disable이 쓰는 목록과 같아요. 프로젝트의 .mcp.json에 있는 서버는 .claude/settings.local.json의 disabledMcpjsonServers에 넣고, 모든 계정에 한꺼번에 적용됩니다.

Codex 서버는 enabled = false로 끕니다. 이 프로젝트에서만 끌 때는 프로젝트의 .codex/config.toml에 적습니다. 모든 프로젝트에서 끄는 건 내가 추가한 서버만 되고, ~/.codex/config.toml에 적습니다.

켜고 끄는 방법이 다른 것도 있습니다.

  • hook은 Claude Code에도 Codex에도 프로젝트별 스위치가 없습니다. 그래서 끄면 모든 프로젝트에서 꺼집니다. 설정 파일에서 빼낸 hook은 clausona가 보관해 두었다가, g로 다시 켤 때 돌려놓습니다.
  • 플러그인에 딸린 것은 플러그인째 켜고 끕니다. 플러그인의 MCP 서버만은 예외로, 계정마다 프로젝트별로 따로 끌 수 있습니다.
  • Codex 플러그인은 목록에만 나오고, 켜고 끄는 건 Codex에서 /plugins로 합니다.
  • 프로젝트의 .mcp.json에 있는 서버는 프로젝트별로만 끌 수 있습니다. Claude Code에 모든 프로젝트용 스위치가 없거든요.

바꿀 수 없는 행이면 아무 창도 뜨지 않고, 아래 상태 줄에 이유가 나옵니다.

안 쓰는 스킬 정리하기

스킬은 금방 쌓입니다. 한 번 써 보고 잊은 스킬도 지우기 전까지는 계속 불러오거든요.

왼쪽의 Not used in 90 days 줄은 어느 계정에서도 90일 동안 쓰지 않은 Claude 스킬을 모아 보여 줍니다. 한 번도 안 쓴 스킬은 만든 지 14일이 지나면 여기 들어가요.

사용 횟수는 모든 계정을 합쳐 셉니다. 그래서 개인 계정에서는 한 번도 안 썼더라도, 회사 계정에서 매일 쓰는 스킬이라면 이 목록에 나오지 않습니다.

clausona skills ls --scope unused --tool claude

d를 누르면 고른 스킬을 지웁니다. x로 여러 행을 표시해 두면 한꺼번에 지울 수도 있어요. 폴더는 바로 없애지 않고 백업으로 옮깁니다. 스킬이 링크라면 링크만 지우고, 링크가 가리키는 폴더는 남겨 둡니다.

git이 추적하는 스킬은 저장소의 일부라서, 지우면 저장소가 바뀝니다. 화면에서는 확인 창에 경고가 뜨고, 대신 이 프로젝트에서 끄는 선택지도 나옵니다. 명령줄에서는 --tracked를 붙여야만 진행합니다.

Cloud 스킬은 claude.ai에서 다시 내려오니 지우지 말고 꺼 두세요. 플러그인은 Claude Code에서 /plugin으로 제거합니다.

되돌리기

모든 변경은 백업부터 합니다. 파일을 고치기 전에 ~/.clausona/backups/extensions/에 복사해 두고, 지운 폴더도 여기로 옮깁니다. 최근 50번의 변경까지 보관합니다.

화면에서 u를 누르면 가장 최근 변경을 되돌립니다. 되돌리기 전에도 한 번 물어봐요. 명령줄에서는 종류마다 따로 되돌립니다.

clausona skills undo
clausona mcp undo
clausona hooks undo

한 번 더 실행하면 그 전 변경까지 되돌려요.

되돌릴 때는 바꾼 내용이 그대로 남아 있는 파일만 되돌립니다. 그사이 나나 Claude Code가 그 내용을 고쳤다면 그 파일은 건드리지 않고, 그렇다고 알려 줍니다. Claude Code가 수시로 다시 쓰는 .claude.json 같은 JSON 파일은 바꾼 키만 봅니다.

명령줄과 에이전트에서 쓰기

화면에서 하는 일은 모두 명령으로도 할 수 있어요. clausona skills, clausona mcp, clausona hooks마다 ls, show, off, on, rm, undo가 있습니다.

clausona skills ls --scope project        # 이 프로젝트가 정의한 스킬
clausona mcp off github --account work    # 이 프로젝트에서 work 계정만 끄기
clausona skills rm old-one --dry-run      # 지우면 무엇이 바뀌는지만 보기

바꾸는 명령은 계획을 먼저 보여 주고 물어봅니다. --dry-run은 계획만 보여 주고 끝나고, --yes는 묻지 않고 진행합니다.

코딩 에이전트는 질문에 답할 터미널이 없으니 --yes가 필요해요. --json을 붙이면 계획과 오류까지 모두 JSON 하나로 출력합니다.

모든 범위와 옵션, 에이전트용 예시는 Extensions 문서(영문)에 있습니다.

자주 묻는 질문

다른 계정에서는 MCP 서버가 안 보이는데 왜 그런가요?

claude mcp add로 추가한 서버는 추가한 계정의 .claude.json에만 들어가고, clausona는 이 파일을 계정끼리 공유하지 않습니다. MCP 화면에서 m을 누르면 어느 계정에 있는지 보여요. 다른 계정에도 추가하거나, 모든 계정이 읽는 프로젝트의 .mcp.json에 넣으세요.

스킬을 끄면 지워지나요?

아니요. 끄기는 설정을 한 줄 적을 뿐이고, 스킬 폴더는 그대로 있습니다. Claude Code 스킬은 설정 파일의 skillOverrides에, Codex 스킬은 config.toml에 적습니다. 끌 때 누른 키를 한 번 더 누르거나 clausona skills on을 실행하면 다시 켜져요. 모든 프로젝트에서 껐다면 --everywhere를 붙입니다. 지우기는 따로 하는 일이고, 그때는 폴더를 백업으로 옮깁니다.

MCP 서버를 한 프로젝트에서만 끌 수 있나요?

네. 계정의 .claude.json에 있는 서버나 플러그인에 딸린 서버는 계정마다 끕니다. 그 계정의 프로젝트 항목에 있는 disabledMcpServers에 이름을 넣는데, /mcp disable이 쓰는 목록과 같습니다. 이 항목은 그 프로젝트를 한 번이라도 연 계정에만 있습니다. 프로젝트의 .mcp.json에 있는 서버는 모든 계정에 한꺼번에 적용됩니다. 프로젝트의 .claude/settings.local.json에서 disabledMcpjsonServers에 이름을 넣고 enabledMcpjsonServers에서는 뺍니다. Codex 서버는 Codex가 신뢰하는 프로젝트라면 그 프로젝트의 .codex/config.toml에 enabled = false를 적어 끕니다.

hook도 프로젝트마다 끌 수 있나요?

아니요. Claude Code에도 Codex에도 hook 하나를 한 프로젝트에서만 끄는 스위치가 없어서, 끄면 모든 프로젝트에서 꺼집니다. 설정 파일에서 빼낸 hook은 clausona가 보관해 두었다가 다시 켤 때 돌려놓습니다.

저장소 파일이 바뀌나요?

Claude 스킬이나 .mcp.json 서버를 이 프로젝트에서 끄면 프로젝트의 .claude/settings.local.json에 적습니다. Claude Code는 전역 git ignore 파일에 한 줄을 넣어 이 파일을 git에서 빼는데, clausona도 이 파일을 새로 만들 때 git이 아직 무시하지 않으면 같은 줄을 넣습니다. 저장소의 스킬 폴더나 프로젝트의 .codex/config.toml처럼 git이 추적하는 파일을 바꾸려면, 명령줄에서는 --tracked를 붙이고 화면에서는 확인 창에서 직접 승인해야 합니다.

API 키나 토큰이 화면에 나오나요?

아니요. MCP 서버의 env와 header는 이름만 보여 주고 값은 보여 주지 않습니다. 명령줄이나 URL에서 비밀 값처럼 보이는 부분은 <hidden>으로 가립니다. 컴퓨터 밖으로 나가는 것도 없습니다. 다만 백업에는 비밀 값까지 그대로 들어 있어서, 백업 폴더는 나만 읽을 수 있게 만듭니다.

Codex에서도 되나요?

네. Codex 탭에서 Codex가 그 프로젝트에서 불러오는 스킬, MCP 서버, hook을 볼 수 있습니다. Codex는 신뢰하는 프로젝트의 .codex 폴더만 읽고, clausona도 그대로 따릅니다. Codex 플러그인은 목록에 나오지만, 켜고 끄는 건 Codex에서 /plugins로 합니다.
