clausona / 에이전트 병렬 실행

Orca에서 Claude Code와 Codex 에이전트를 계정별로 병렬 실행하기

Orca는 에이전트마다 worktree와 탭을 따로 줍니다. 여기에 clausona를 더하면 Claude Code(클로드 코드)나 Codex 에이전트마다 계정도 따로 쓸 수 있어요. DeepSeek 같은 API 모델도 됩니다.

2026년 10월 10일 업데이트

orca-fleet 플러그인을 설치합니다. 조율 플러그인들이 함께 쓰는 규칙인 fleet-core도 같이 설치됩니다.

claude plugin marketplace add larcane97/clausona
claude plugin install orca-fleet@clausona

그다음 Orca 터미널에서 Claude Code에게 이렇게 요청합니다. "이 작업들을 Orca에서 내 계정들에 나눠 줘: CODE_OF_CONDUCT.md는 claude:side에서 Sonnet으로 쓰고, .prettierrc는 DeepSeek로 추가해 줘."

그러면 계획을 세우고, 작업마다 Orca worktree를 하나씩 만들어 워커를 띄웁니다. 각 워커는 정해진 계정으로 돌아가요. 정리하기 전에는 워커가 낸 결과를 직접 확인합니다.

Orca에서 보이는 것

워커는 Orca 사이드바에 worktree로 하나씩 나타납니다. 이름에 하는 일과 clausona 프로필이 붙어 있어서, 어느 계정이 무엇을 하는지 한눈에 보여요.

Claude Code 워커는 작업 중인지 끝났는지도 사이드바에 표시됩니다. orca worktree ps로는 마지막 답변을 볼 수 있고요. Orca의 hook은 clausona가 공유하는 Claude Code 설정에 들어 있어서, 어느 프로필로 띄워도 이렇게 보입니다.

워커 탭을 열어 직접 입력할 수도 있습니다. 하나가 엉뚱한 쪽으로 가면 그것만 멈추고, 나머지는 그대로 두면 됩니다.

실행 흐름

메인 세션은 먼저 clausona list로 프로필을 읽고 작업마다 하나씩 고릅니다. 요청에도 fleet.json에도 계정이 정해져 있지 않으면, 계획을 보여 주고 확인을 기다립니다.

그다음 작업마다 orca worktree create로 worktree를 만들고 그 안에 터미널을 엽니다. 셸이 준비되면 고른 프로필로 clausona run 명령을 입력합니다.

Orca에는 자체 계정 전환 기능이 있고, 터미널마다 CODEX_HOME도 설정해 둡니다. clausona run은 자기가 띄우는 워커에서 이 값을 덮어씁니다. 그래서 탭마다 계획에서 정한 계정으로 돌아가요.

브리프는 worktree 안에 파일로 넣고, 워커에게는 그 파일을 읽으라는 한 줄만 보냅니다. 워커 화면이 조용해지면 Orca의 terminal wait가 메인 세션에 알려 줍니다.

워커가 끝났다고 하면 메인 세션이 직접 확인합니다. 커밋과 diff를 보고, 브랜치가 깨끗한 상태로 push됐는지도 봅니다.

확인이 끝나면 orca worktree rm으로 worktree를 지웁니다. 기본값은 사용자가 승인한 뒤에 지우는 것이고, retire가 auto면 바로 지웁니다. 커밋하지 않은 변경이 있으면 Orca가 지우지 않습니다. 다만 Orca는 로컬 브랜치까지 함께 지우기 때문에 push 확인을 먼저 합니다.

Orca는 worktree를 홈 폴더 아래 ~/orca/workspaces에 둡니다. 그래서 홈에 ~/.mcp.json이 있으면 Claude Code가 "new MCP servers" 질문에서 멈춰요. Claude Code 워커를 --strict-mcp-config로 띄우는 이유입니다.

Codex를 메인 세션으로 쓰기

Codex도 조율을 맡을 수 있습니다. Codex에 플러그인을 설치하면 되는데, Codex는 플러그인 의존성을 지원하지 않아서 fleet-core를 따로 추가해야 합니다.

codex plugin marketplace add larcane97/clausona
codex plugin add fleet-core@clausona
codex plugin add orca-fleet@clausona

Codex로 조율하면 워커도 기본으로 Codex 계정을 씁니다. Claude Code로 조율하면 Claude Code 계정을 쓰고요. 다른 도구의 프로필은 직접 지정하거나 workers에 넣어 둔 경우에만 워커가 됩니다.

Codex 워커는 Orca 사이드바에 상태가 나오지 않습니다. Orca의 Codex hook이 Orca 전용 Codex 폴더에 있기 때문이에요. 대신 메인 세션이 워커 화면을 읽습니다.

Codex 기본 샌드박스에서는 Codex 워커가 .git에 쓸 수 없고 네트워크에도 나가지 못합니다. 그래서 커밋 전에 한 번, push 전에 또 한 번 승인을 물어요. 워커 탭에서 승인하면 됩니다.

알아서 하게 하려면 아래 설정 파일의 permissions에 "codexSandbox": "danger-full-access"를 넣으세요. 이러면 워커의 Codex 샌드박스가 꺼집니다.

설정

조율 플러그인들은 ~/.clausona/fleet.json 파일 하나를 함께 씁니다. 워커로 쓸 프로필 목록, 자연어로 적은 배정 규칙, 사용량 한도, 끝난 워커를 자동으로 정리할지를 여기에 적습니다. 각 키의 설명은 에이전트 병렬 실행 가이드에 있습니다.

말로 해도 됩니다. "끝난 워커는 항상 정리해"라고 하면 메인 세션이 파일을 고쳐요.

자주 묻는 질문

Orca가 켜져 있어야 하나요?

네. orca 명령은 실행 중인 앱과 통신하므로 같은 컴퓨터에서 Orca를 켜 두세요. 메인 세션은 Orca 터미널에서 돌려도 되고, 같은 컴퓨터의 다른 터미널에서 돌려도 됩니다.

Windows와 Linux에서도 되나요?

됩니다. Orca와 clausona 모두 macOS, Windows, Linux에서 돌아가고, 플러그인은 세 OS 모두에서 같은 orca 명령으로 Orca를 다룹니다. Windows의 Codex 메인 세션은 명령을 PowerShell로 실행하는데, 플러그인이 PowerShell용 명령도 알려 줍니다.

워커를 정리하다 작업이 날아갈 수 있나요?

Orca는 worktree를 지울 때 로컬 브랜치도 함께 지웁니다. 그래서 메인 세션은 브랜치가 push되고 worktree가 깨끗할 때만 워커를 정리해요. orca worktree rm은 커밋하지 않은 변경이 있는 worktree를 지우지 않고, 메인 세션은 강제로 지우지 않습니다.

Orca 탭마다 다른 계정을 쓰려면 플러그인이 꼭 필요한가요?

아니요. 어느 Orca 터미널에서든 clausona run claude:work를 실행하면 그 탭은 그 계정으로 돌아갑니다. 플러그인은 그 위에 작업을 나누고 결과를 확인하는 조율 세션을 더합니다.
