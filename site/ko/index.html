Claude Code와 Codex 계정 여러 개를 동시에 쓰는 법

회사 계정과 개인 계정을 오가며 Claude Code(클로드 코드)나 Codex를 쓰면 바꿀 때마다 다시 로그인해야 합니다. 스킬과 플러그인은 계정마다 따로 설치해야 하고 대화 기록도 계정별로 흩어집니다. 이 글은 로그인만 계정마다 따로 두고 스킬, 훅, 플러그인, 설정은 하나로 공유하는 방법을 정리합니다. 원하면 대화 기록도 공유할 수 있습니다.

2026년 10월 8일 업데이트

요약 계정마다 설정 폴더를 따로 두고(Claude Code는 CLAUDE_CONFIG_DIR, Codex는 CODEX_HOME), 로그인 정보를 뺀 나머지를 기본 폴더에 연결합니다. clausona를 쓰면 명령 세 개로 끝납니다.

clausona init              # 이미 로그인된 계정 등록
clausona add claude:work   # 계정 추가, Claude Code 로그인 화면이 열림
csn use work               # 이제 그냥 `claude`가 이 계정으로 시작

계정을 하나 더 쓰기 번거로운 이유

Claude Code는 한 번에 계정 하나만 로그인됩니다. /logout과 /login으로 바꿀 수는 있지만 바꿀 때마다 다시 로그인해야 합니다. 한 터미널은 회사 계정으로, 다른 터미널은 개인 계정으로 동시에 쓸 수도 없습니다. Codex도 ~/.codex의 auth.json 하나로 로그인하니 사정이 같습니다.

환경 변수 CLAUDE_CONFIG_DIR와 CODEX_HOME으로 설정 폴더를 하나 더 만들면 로그인을 따로 둘 수 있습니다. 문제는 새 폴더가 빈 상태로 시작한다는 점입니다. 설정, 훅, 스킬, 플러그인, 전역 지침(CLAUDE.md, AGENTS.md), 대화 기록이 하나도 없습니다. 한쪽 계정에 플러그인을 설치해도 다른 쪽에는 없어서 두 환경은 점점 달라집니다.

Claude Code 직접 설정하기

~/.claude를 기본 폴더로 두고, 두 번째 계정용 폴더를 만들어 공유할 것만 연결합니다.

# 두 번째 계정용 폴더
mkdir -p ~/.claude-work

# 두 계정이 함께 쓸 것을 연결
for item in settings.json CLAUDE.md skills commands agents hooks; do
  [ -e ~/.claude/$item ] && ln -sn ~/.claude/$item ~/.claude-work/$item
done

# 그 폴더로 Claude Code를 열고 두 번째 계정으로 로그인
CLAUDE_CONFIG_DIR=~/.claude-work claude

# 계정별 별칭
alias claude-work='CLAUDE_CONFIG_DIR=~/.claude-work claude'

훅은 settings.json에 설정되므로 이 파일을 연결하면 훅과 권한, 상태 표시줄, 모델 설정이 함께 공유됩니다.

공유하면 안 되는 것도 있습니다.

  • .claude.json: 어느 계정이 로그인됐는지와 claude mcp add로 추가한 MCP 서버가 들어 있습니다. 연결하면 폴더마다 어느 계정인지가 뒤섞입니다. MCP 서버는 계정마다 추가하거나 프로젝트의 .mcp.json에 두세요.
  • .credentials.json: Linux와 Windows의 로그인 토큰입니다. macOS는 설정 폴더 경로에서 이름을 만든 키체인 항목에 토큰을 따로 둡니다.
  • plugins/ 통째로: 안의 known_marketplaces.json과 installed_plugins.json에 설정 폴더의 절대경로가 들어 있습니다. 나머지는 연결하고, 이 두 파일은 폴더마다 경로를 고친 사본을 둔 뒤 플러그인을 바꿀 때마다 맞춰야 합니다.

기본 계정에는 CLAUDE_CONFIG_DIR를 설정하지 마세요. 값을 ~/.claude로 줘도 Claude Code는 별도 폴더로 취급해서 ~/.claude.json 대신 ~/.claude/.claude.json을 읽고, macOS에서는 다른 키체인 항목을 찾습니다. 로그인되지 않은 다른 사용자가 되는 셈입니다(Claude Code 2.1.278, macOS에서 확인).

Codex 직접 설정하기

Codex는 홈 폴더에 설정 말고도 계정 상태를 많이 둡니다. 그래서 홈을 통째로 연결하지 말고 공유할 항목만 골라 연결해야 합니다.

mkdir -p ~/.codex-work
for item in config.toml hooks.json AGENTS.md rules skills plugins agents prompts; do
  [ -e ~/.codex/$item ] && ln -sn ~/.codex/$item ~/.codex-work/$item
done
CODEX_HOME=~/.codex-work codex login
alias codex-work='CODEX_HOME=~/.codex-work codex'

계정마다 따로 둬야 하는 것은 다음과 같습니다(Codex CLI 0.159에서 확인).

  • auth.json: 로그인 정보입니다.
  • app-server-control/, app-server-daemon/: Codex는 백그라운드 데몬을 띄우고 이 폴더로 찾아갑니다. 공유하면 다른 계정의 데몬에 붙어서 엉뚱한 계정으로 실행됩니다.
  • memories/, memories_1.sqlite: 지난 대화 요약을 이후 프롬프트에 넣는 기억입니다. 공유하면 한 계정의 대화가 다른 계정 프롬프트에 섞입니다.
  • 그 밖의 SQLite DB와 -wal, -shm 파일, .env(계정별 API 키가 있을 수 있음), packages/(데몬 설치본).

홈 경로는 짧게 두세요. 데몬이 홈 안에 유닉스 소켓을 만드는데, 경로가 100바이트 안팎을 넘으면 데몬 자동 업데이트가 아무 말 없이 멈춥니다.

clausona로 하기

clausona는 위 과정을 대신하고 이후에도 연결이 어긋나지 않게 관리하는 무료 오픈소스 CLI입니다. Claude Code와 Codex를 모두 지원합니다.

macOS, Linux curl -fsSL https://github.com/larcane97/clausona/releases/latest/download/install.sh | bash
Windows PowerShell irm https://github.com/larcane97/clausona/releases/latest/download/install.ps1 | iex

Node.js 20 이상과 Claude Code 또는 Codex CLI가 필요합니다.

clausona init              # 이미 로그인된 Claude Code와 Codex 계정 등록
clausona add claude:work   # ~/.claude-work를 만들고 Claude Code 로그인을 엶
clausona add codex:work    # ~/.codex-work를 만들고 Codex 로그인을 실행
csn use claude:work        # 이제 그냥 `claude`가 회사 계정으로 시작
csn use codex:work         # Codex도 같은 방식

계정마다 폴더가 따로 생깁니다. Claude Code는 로그인 정보와 계정 상태를 뺀 나머지를, Codex는 정해 둔 설정 목록만 기본 폴더에 연결합니다. 그래서 설정, 훅, 스킬, 플러그인, 전역 지침이 모든 계정에서 같습니다. 플러그인 파일 두 개도 계정마다 자동으로 맞춰 줍니다. Claude Code가 업데이트되면서 생긴 새 폴더처럼 연결이 빠진 곳은 clausona doctor가 알려 주고 clausona repair <프로필>이 고칩니다. csn은 clausona의 짧은 이름입니다.

clausona는 Claude Code나 Codex를 감싸거나 프록시하지 않습니다. claude나 codex를 실행할 때마다 셸 훅이 계정 폴더를 지정하고 원래 명령을 그대로 실행합니다.

설치되는 것과 실행 부담

clausona는 도구가 시작되기 전에 계정을 맞춰 놓을 뿐, 세션이 시작된 뒤에는 관여하지 않습니다. 띄워 둘 앱도, 계속 떠 있는 서비스도 없습니다.

claude를 실행할 때
셸이 캐시해 둔 실행 스크립트를 읽고 원래 실행 파일을 그대로 실행합니다. M4 Pro Mac에서 claude --version의 실행 시간 중앙값은 훅이 있을 때와 없을 때 모두 25ms였습니다(Claude Code 2.1.294, 각 15회).
clausona가 직접 실행될 때
csn use나 플러그인 설치처럼 무언가를 바꾼 뒤에만 실행됩니다. clausona를 한 번 띄우는 데 0.3초쯤 걸려서 평소 실행에서는 건너뜁니다.
설치되는 것
1MB 남짓한 JavaScript 파일 하나, 셸 설정 파일에 들어가는 훅, 공유할 파일과 폴더마다 만드는 심볼릭 링크가 전부입니다. 업데이트는 릴리스의 SHA-256과 대조한 뒤에 적용합니다.
지울 때
clausona uninstall이 훅과 링크, ~/.clausona를 지웁니다. 아직 데이터가 남은 백업은 남겨 두고, 계정 폴더와 대화 기록도 그대로 둡니다.

대화 기록까지 공유하기

대화 기록은 기본적으로 계정마다 따로 둡니다. 계정별로 기록 공유를 켜면 그 계정이 기본 폴더와 대화 기록을 함께 씁니다.

clausona config claude:work --merge-sessions
clausona config codex:work --merge-sessions
  • Claude Code: 켜는 순간 그 계정의 기존 대화를 공유 기록으로 복사하므로 사라지는 대화는 없습니다. 이후 claude --resume은 기록을 공유하는 모든 계정의 대화를 보여 줍니다. claude --continue는 어느 계정에서 시작했든 현재 폴더의 마지막 대화를 이어 가고, 대화에 걸어 둔 /goal도 함께 돌아옵니다.
  • Codex: macOS와 Linux에서는 codex resume과 codex resume --last가 모든 계정의 스레드를 찾고 스레드의 goal도 함께 돌아옵니다. Claude Code와 달리 그 계정의 기존 Codex 대화는 공유 기록으로 복사되지 않습니다. ~/.clausona/backups/codex/<프로필>/에 보관했다가 --separate-sessions로 끄면 되돌립니다. 기억(memories)은 이때도 계정마다 따로 남습니다. 켜기 전에 그 계정의 Codex를 종료하고 데몬도 멈추세요(CODEX_HOME=~/.codex-work codex app-server daemon stop). Windows에서는 스레드 저장소가 계정마다 따로 남아서 다른 계정의 스레드는 ID로 이어야 합니다.

직접 하려면 Claude Code는 projects/, jobs/, teams/를 함께 공유해야 합니다. 셋이 세션 ID로 서로를 가리켜서 하나만 공유하면 백그라운드 세션을 이어갈 수 없습니다. 끄려면 --separate-sessions를 씁니다.

두 계정 동시에 쓰고 사용량 한눈에 보기

csn use는 새로 여는 claude와 codex가 쓸 계정을 정합니다. 기본 계정은 그대로 두고 세션 하나만 다른 계정으로 띄우려면 clausona run을 씁니다. 한 터미널은 회사 계정으로 열고 다른 터미널을 개인 계정으로 열어도 스킬과 훅은 같습니다.

clausona run claude:default

clausona list는 모든 계정의 5시간 한도와 주간 한도 사용량, 초기화까지 남은 시간을 나란히 보여 줍니다. 각 도구가 계정마다 저장해 둔 로그인으로 그 도구의 사용량 정보를 읽습니다.

PROFILE             ACCOUNT              5H         7D
claude:work         dev@example.com      62% 1h     41% 3d
claude:personal     me@example.org       8%         77% 5d
codex:work          dev@example.com      —          12% 5d

자주 묻는 질문

Claude Code 계정 두 개를 한 컴퓨터에서 같이 쓸 수 있나요?

네. Claude Code는 설정 폴더 하나에 계정 하나가 로그인됩니다. 계정마다 설정 폴더를 따로 두면 여러 계정을 로그인해 둔 채 쓸 수 있습니다. clausona는 스킬, 훅, 플러그인, 설정을 기본 폴더 ~/.claude와 공유하도록 연결해 줍니다.

다른 계정에서 대화를 이어갈 수 있나요?

네. clausona config <프로필> --merge-sessions로 기록 공유를 켜면 claude --resume과 claude --continue가 기록을 공유하는 모든 계정의 대화를 찾습니다. macOS와 Linux에서는 codex resume도 마찬가지입니다.

clausona를 쓰면 Claude Code 실행이 느려지나요?

아니요. 평소에는 셸이 캐시해 둔 실행 스크립트만 읽습니다. M4 Pro Mac에서 claude --version의 실행 시간 중앙값은 훅이 있을 때와 없을 때 모두 25ms였습니다. clausona 자체는 csn use처럼 설정을 바꾼 뒤에만 실행됩니다.

로그인 정보도 공유되나요?

아니요. 로그인 정보는 계정마다 따로 있고 공유되지 않습니다.

한도에 걸리면 자동으로 다른 계정으로 바꿔 주나요?

아니요. 터미널마다 어느 계정을 쓸지는 직접 고르고, clausona는 계정마다 한도가 얼마나 남았는지 보여 줍니다. 계정은 회사용, 개인용처럼 용도에 맞게 쓰고 Anthropic과 OpenAI 약관을 지켜 주세요.

Claude Code와 Codex의 설정도 서로 공유되나요?

아니요. Claude Code 계정끼리 ~/.claude를, Codex 계정끼리 ~/.codex를 공유합니다.

API 키나 다른 모델도 프로필로 쓸 수 있나요?

네, Claude Code는 됩니다. clausona add claude:gw --api --base-url <url>로 Anthropic API, OpenRouter 같은 게이트웨이, 직접 띄운 모델을 프로필로 추가할 수 있고 다른 계정처럼 전환됩니다.

Windows에서도 되나요?

네, PowerShell 5.1 이상에서 됩니다. 공유 폴더는 정션으로 연결됩니다. 개발자 모드를 켜 두세요. 꺼져 있으면 settings.json, CLAUDE.md처럼 저장할 때마다 통째로 바뀌는 파일이 계정마다 사본으로 남고, clausona doctor가 이를 알려 줍니다.

clausona 써 보기

무료 오픈소스입니다. 하루에 로그인 몇 번이라도 줄여 줬다면 GitHub에 별을 눌러 주세요. 다른 사람이 찾는 데 도움이 됩니다. 에이전트 여러 개를 계정마다 나눠 돌리려면 에이전트 병렬 실행 가이드를 보세요.

clausona는 MIT 라이선스 오픈소스로 GitHub에 있으며, Awesome Claude Code에 소개되었습니다.

Anthropic, OpenAI와 관계없는 개인 프로젝트입니다. Claude Code는 Anthropic 제품이고 Codex CLI는 OpenAI 제품입니다.
