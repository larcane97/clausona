Codex CLI 계정 여러 개 쓰는 법: 로그아웃 없이 계정 전환하고 대화 이어가기

Codex CLI에서 두 번째 계정으로 로그인하면 기존 로그인이 풀려 버립니다. 회사 계정과 개인 계정을 오가며 쓰다 보면 바꿀 때마다 매번 다시 로그인하게 되죠.

2026년 11월 9일 업데이트

Codex CLI는 로그인 정보부터 온갖 설정까지 모두 홈 폴더 하나에 모아 둡니다. 기본 경로인 ~/.codex 폴더입니다.

이 홈 폴더를 계정마다 따로 두면 로그아웃하지 않고도 계정을 바로 바꿀 수 있어요.

방법 자체는 간단합니다. 계정마다 CODEX_HOME으로 홈 폴더를 따로 지정하고, 설정 파일만 기본 폴더인 ~/.codex에 연결하면 됩니다. 어느 계정으로 열어도 스킬과 hook이 같고 설정도 그대로 유지됩니다.

다만 홈 폴더를 통째로 연결하지는 마세요. 백그라운드 데몬이나 지난 대화 기억(memories)까지 뒤섞여서 다른 계정 일까지 대신 맡게 됩니다.

clausona를 쓰면 명령 세 개로 끝납니다.

clausona init              # 이미 로그인된 홈 등록
clausona add codex:work    # 두 번째 계정, 로그인은 Codex 자체 로그인으로
csn use codex:work         # 이제 그냥 `codex`가 이 계정으로 시작

CODEX_HOME으로 계정 전환 직접 설정하기

홈 폴더가 하나뿐이면 로그인 정보가 담긴 auth.json도 하나뿐입니다. 로그아웃하고 다시 로그인할 때마다 이 파일이 덮어써지고, 두 계정을 서로 다른 터미널에 동시에 띄울 수도 없습니다.

이럴 때 Codex가 어느 홈 폴더를 쓸지 정하는 환경 변수인 CODEX_HOME을 쓰면 계정마다 홈을 따로 둘 수 있습니다.

직접 설정하는 방법부터 볼게요. ~/.codex를 기본 홈으로 두고, 두 번째 계정용 홈에는 공유할 설정만 골라 연결합니다.

# 두 번째 계정용 홈
mkdir -p ~/.codex-work

# 두 계정이 함께 쓸 설정을 연결
for item in config.toml hooks.json AGENTS.md rules skills plugins agents prompts; do
  [ -e ~/.codex/$item ] && ln -sn ~/.codex/$item ~/.codex-work/$item
done

# 두 번째 계정은 자기 홈에서 로그인
CODEX_HOME=~/.codex-work codex login

MCP 서버와 Codex 프로필은 config.toml에 들어 있습니다. 그래서 이 파일을 연결하면 두 설정도 함께 공유돼요.

마지막으로 셸 별칭을 하나 만들어 두면 편합니다.

alias codex-work='CODEX_HOME=~/.codex-work codex'

홈 경로는 짧게 두세요. Codex의 app-server 데몬이 CODEX_HOME 안에 유닉스 소켓을 만드는데, macOS와 Linux에서는 소켓 경로가 100바이트 안팎을 넘기면 데몬 자동 업데이트가 아무 말 없이 멈춥니다. ~/.codex-work 정도 길이면 괜찮아요.

계정마다 따로 둬야 하는 것

Codex는 홈 폴더에 설정 말고도 계정 상태를 꽤 많이 둡니다. 새 버전이 나올 때마다 파일이 조금씩 더 늘어나기도 하고요.

계정마다 따로 둬야 하는 항목은 다음과 같습니다(Codex CLI 0.159에서 확인).

  • auth.json에는 로그인 정보가 들어 있습니다. 그 밖의 토큰은 .credentials.json과 secrets/에 저장됩니다.
  • app-server-control/과 app-server-daemon/은 백그라운드 데몬이 쓰는 폴더입니다. Codex는 app-server 데몬을 띄운 뒤 app-server-control/로 그 데몬을 찾아갑니다. 이 폴더를 기본 홈과 연결해 두면 기본 계정의 데몬에 붙어서 엉뚱한 계정으로 실행됩니다. 한쪽 홈에서 데몬을 멈추면 다른 홈의 데몬까지 같이 멈추고요.
  • memories/와 memories_1.sqlite에는 지난 대화 요약이 쌓입니다. Codex는 이 요약을 다음 프롬프트에 넣습니다. 그래서 공유하면 한 계정에서 나눈 대화가 다른 계정의 프롬프트에 섞여 들어갑니다.
  • 그 밖의 SQLite 데이터베이스도 -wal, -shm 파일까지 함께 따로 둡니다. 계정별 작업 큐나 실행 로그 같은 상태 정보가 들어 있거든요.
  • .env는 Codex가 켜질 때 환경 변수로 읽어 들이는 파일입니다. 계정별 API 키가 들어 있을 수 있어요.
  • packages/는 300MB쯤 되는 데몬 설치본입니다. 공유해 두면 한쪽에서 업데이트할 때 모든 홈이 쓰는 데몬이 한꺼번에 바뀝니다.

그래서 홈 전체를 연결해 놓고 파일 몇 개만 빼기보다, 위에서처럼 공유할 항목을 하나하나 정해 연결하는 편이 안전합니다.

이렇게 해 두면 새 Codex 버전이 만든 파일은 그 계정에 따로 남습니다. 공유할지 말지는 나중에 직접 정하면 돼요.

clausona로 여러 계정 설정하기

clausona는 홈 폴더를 이 방식대로 만들어 주는 무료 오픈소스 계정 전환 도구입니다. Claude Code도 똑같이 관리해 줍니다.

macOS, Linux curl -fsSL https://github.com/larcane97/clausona/releases/latest/download/install.sh | bash
Windows PowerShell irm https://github.com/larcane97/clausona/releases/latest/download/install.ps1 | iex

평소처럼 Codex에 첫 계정을 로그인해 둔 다음, 아래 명령을 실행합니다.

clausona init              # ~/.codex와 이미 로그인된 다른 홈 등록
clausona add codex:work    # ~/.codex-work를 만들고 Codex 로그인 실행
csn use codex:work         # 이제 그냥 `codex`가 회사 계정으로 시작

clausona는 미리 정해 둔 설정 목록만 기본 홈에 연결합니다. 나머지 파일은 각 계정에 그대로 남습니다.

예전 버전의 clausona로 만든 홈이라면 데몬 폴더나 기억처럼 분리해야 할 계정 상태가 아직 연결돼 있을 수 있습니다. 이런 홈은 clausona doctor가 찾아서 알려 줍니다.

clausona repair <프로필>을 실행하면 잘못된 연결을 끊고, 백업에서 그 계정 몫의 사본을 되돌려 놓습니다. 그 과정에서 지워지는 파일은 없습니다.

참고로 csn은 clausona의 짧은 이름이에요.

실행 원리도 가볍습니다. 셸 hook이 그 세션에 쓸 CODEX_HOME만 정해 주고 원래 codex를 바로 띄웁니다. Codex를 감싸는 래퍼도 없고, 백그라운드에서 도는 프로세스도 없습니다.

평소에 그냥 codex로 실행할 때는 clausona 자체를 건너뜁니다. clausona가 실제로 실행되는 건 csn use codex:work처럼 설정을 바꾼 직후의 첫 실행 때뿐입니다. 물론 clausona run으로 띄우면 route를 쓰든 안 쓰든 매번 실행되고요.

계정을 바꿔도 대화 이어 가기

회사 계정에서 하던 대화를 개인 계정으로 넘겨받아 이어 가고 싶을 때가 있습니다.

Codex는 대화 내용을 sessions/에 두고, 그 옆에 history.jsonl과 session_index.jsonl을 둡니다. 여기에 데이터베이스 세 개도 함께 움직여요.

  • Codex가 스레드를 찾을 때 쓰는 state_5.sqlite
  • 스레드의 /goal을 저장하는 goals_1.sqlite
  • 대화 파일의 색인인 thread_history_1.sqlite

다른 계정에서 대화를 이어 가려면 이 파일들을 전부 함께 공유해야 합니다.

직접 연결할 때는 데이터베이스를 조심해서 다뤄야 합니다. 링크는 원본 데이터베이스 파일에만 걸고, -wal이나 -shm에는 걸지 마세요. SQLite가 링크가 가리키는 원본 파일 옆에 이 두 파일을 직접 만들어 쓰기 때문입니다.

clausona에서는 계정마다 옵션 하나만 켜면 됩니다.

먼저 그 계정의 Codex를 닫고 백그라운드 데몬도 멈추세요.

CODEX_HOME=~/.codex-work codex app-server daemon stop

macOS와 Linux에서는 Codex나 데몬 중 하나라도 실행 중이면 clausona가 파일을 옮기지 않습니다.

데몬이 멈췄다면 기록 공유를 켭니다.

clausona config codex:work --merge-sessions

이제 macOS와 Linux에서는 codex resume과 codex resume --last가 기록을 공유하는 모든 계정의 스레드를 찾아 줍니다. 이어 간 스레드의 goal도 그대로 돌아와요.

다만 Claude Code와 달리, 그 계정에 원래 있던 기존 Codex 대화는 공유 기록으로 합쳐지지 않습니다. 대신 ~/.clausona/backups/codex/<프로필>/에 따로 보관해 두었다가, 나중에 --separate-sessions로 공유를 끄면 원래대로 되돌려 놓습니다.

대화 기록을 공유해도 기억(memories)은 계정마다 따로 남습니다.

Windows에서는 스레드 저장소가 계정마다 따로 유지됩니다. Windows용 SQLite는 데이터베이스를 연 경로를 기준으로 로그 파일 이름을 정하기 때문이에요. 그래서 Windows에서는 다른 계정의 스레드를 ID로 이어 갑니다.

두 계정 동시에 쓰고 사용량 보기

csn use codex:work는 새로 여는 codex가 기본으로 쓸 계정을 정합니다.

이 기본 설정은 그대로 두고 터미널 세션 하나만 다른 계정으로 띄우고 싶다면 아래처럼 실행합니다.

clausona run codex:default

clausona list를 실행하면 Codex 계정마다 주간 한도를 Claude Code 계정과 나란히 보여 줍니다. 5시간 한도가 있는 요금제라면 그 수치도 같이 나와요. 계정마다 저장된 로그인 정보로 Codex의 사용량 엔드포인트에서 직접 읽어 옵니다.

동적 라우팅으로 여러 계정의 사용량 최적화하기

계정이 두 개 이상이면 한 계정만 바닥날 때까지 쓰고, 다른 계정은 그대로 남겨 두기 쉽습니다.

clausona의 동적 라우팅은 실행할 때마다 계정을 알아서 골라 줍니다. 계정마다 현재 사용량을 확인하고 여유 있는 계정으로 시작해요. 여러 계정을 돌아가며 쓰니 사용량이 한쪽에만 몰리지 않고 고르게 나뉩니다.

동적 라우팅을 쓰려면 먼저 내 계정 몇 개를 묶어 이름을 붙인 route를 만듭니다. 이때 --tool codex를 붙이지 않으면 Claude Code용 route가 만들어집니다.

clausona route add cx --tool codex    # Codex 계정 전부, 돌아가며 사용
clausona route explain cx             # 지금 실행하면 어느 계정이 뽑히는지와 그 이유
clausona run codex --route cx         # 고른 계정으로 Codex 시작

사용량이 80% 아래인 계정이 남아 있는 동안에는 한도를 80% 이상 쓴 계정을 건너뜁니다. 주간 한도는 물론이고, 요금제에 따라 5시간 한도까지 함께 확인합니다. 어느 계정으로 시작했는지는 실행할 때 한 줄로 알려 줍니다.

route에 모든 계정을 넣을 필요는 없습니다. 예를 들어 clausona route add cx-work --tool codex --from '*@work.example'로 만들면 회사 메일 주소로 된 Codex 계정만 묶입니다. 여기에 clausona route dir ~/work cx-work까지 해 두면, ~/work 아래 어디서든 그냥 clausona run codex만 실행해도 회사 계정 중에서 골라 시작합니다.

그냥 codex만 입력해 실행할 때는 route를 거치지 않습니다. 그때는 csn use로 정해 둔 계정으로 시작합니다.

route에 묶인 계정이 모두 한도를 다 쓴 상태라면 아무것도 실행하지 않고, 계정마다 언제 초기화되는지 알려 줍니다. 한도가 풀릴 때까지 기다리는 방법 같은 나머지 설정은 route 문서(영문)에 정리돼 있습니다.

계정을 고르는 건 실행을 시작할 때 한 번뿐입니다. 이미 켜서 쓰고 있는 세션이 도중에 다른 계정으로 옮겨 가는 일은 없어요.

계정은 회사용과 개인용처럼 용도에 맞게 쓰고, OpenAI 약관을 지켜 주세요.

자주 묻는 질문

로그아웃 없이 Codex CLI 계정을 전환하려면 어떻게 하나요?

계정마다 CODEX_HOME을 따로 두고, CODEX_HOME=<폴더> codex login으로 한 번씩 로그인해 두세요. Codex는 지정한 홈 폴더의 계정으로 시작합니다. clausona를 쓴다면 clausona add codex:work를 실행한 다음 csn use codex:work로 바꾸면 됩니다.

codex --profile로 계정을 바꿀 수 있나요?

아니요. --profile은 config.toml에 적어 둔 모델이나 provider 같은 옵션 묶음을 고르는 기능입니다. ChatGPT 로그인 정보는 CODEX_HOME의 auth.json에서 읽어 오기 때문에, 어느 프로필을 골라도 계정은 그대로예요. 두 번째 계정을 쓰려면 CODEX_HOME을 따로 둬야 합니다.

auth.json 파일을 바꿔 끼우면 안 되나요?

처음 한동안은 됩니다. 그런데 Codex는 로그인 토큰을 갱신할 때마다 auth.json을 새로 씁니다. 따로 빼 둔 사본은 이 갱신을 따라가지 못해서, 나중에 그 사본으로 덮어쓰면 다시 로그인해야 할 수도 있어요. 계정마다 CODEX_HOME을 두면 각 로그인이 알아서 최신 상태로 유지됩니다.

~/.codex에서 계정끼리 공유해도 되는 파일은 무엇인가요?

설정 파일들입니다. config.toml과 모든 *.config.toml 파일을 비롯해 hooks.json, AGENTS.md, rules/, skills/, plugins/, agents/, prompts/가 여기에 들어갑니다. 반면에 로그인 정보인 auth.json과 app-server 데몬 폴더는 물론이고 기억(memories)이나 데이터베이스, .env, packages/는 계정마다 따로 두세요.

~/.codex를 통째로 공유하면 안 되나요?

Codex는 홈 폴더에 계정 고유 상태도 함께 둡니다. 예를 들어 app-server-control/을 공유하면 Codex가 다른 계정의 데몬에 붙어서 그 계정으로 실행됩니다. 기억(memories)까지 공유하면 한 계정의 지난 대화가 다른 계정의 프롬프트에 섞여 들어가고요.

Codex와 Claude Code의 설정도 서로 공유되나요?

아니요. Codex 계정끼리 ~/.codex의 설정을 공유하고, Claude Code 계정끼리 ~/.claude의 설정을 공유합니다. 두 도구의 설정은 서로 섞이지 않습니다.

한도에 걸리면 clausona가 다른 계정으로 바꿔 주나요?

이미 실행 중인 세션은 다른 계정으로 옮겨 가지 않습니다. 대신 동적 라우팅을 쓰면 실행을 시작할 때 clausona가 여유 있는 계정을 골라 줍니다. clausona run codex --route cx로 띄우면 그 route의 Codex 계정 중 아직 한도가 남은 계정으로 시작해요. 반면에 clausona use와 clausona run <프로필>은 직접 지정한 계정을 씁니다. 계정은 회사용과 개인용처럼 용도에 맞게 쓰고 OpenAI 약관을 지켜 주세요.
