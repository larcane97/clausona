Claude Code 에이전트를 여러 계정과 모델로 병렬 실행하기

작업 하나를 다섯 갈래로 나눌 때 보통은 Claude Code(클로드 코드)의 서브에이전트를 씁니다. 부모 세션이 다섯 개를 한꺼번에 띄워 놓고, 각자 일을 마치면 돌려준 결과만 받아 보는 식이죠.

2026년 10월 10일 업데이트

그런데 서브에이전트는 일하는 과정이 보이지 않습니다. 다섯 개 중 하나만 골라 끼어들기도 어렵고요. 게다가 다섯 개가 모두 같은 계정을 씁니다.

이 글에서는 에이전트마다 독립된 Claude Code 세션을 띄우는 방법을 다룹니다. 세션마다 지켜보다가 끼어들 수 있고, 각 세션을 정해 둔 계정이나 모델로 보낼 수 있습니다. 회사 계정과 두 번째 구독 계정은 물론, DeepSeek 같은 API 모델도 됩니다.

핵심은 세션마다 프로필을 붙이는 것입니다. clausona로 띄운 세션은 그 프로필(계정이나 API 엔드포인트)로 돌아가고, 띄우는 곳은 어느 실행 환경이든 상관없습니다.

작업을 나누고 맡기는 일까지 넘기고 싶다면 쓰는 도구에 맞는 조율 플러그인을 설치합니다. Superset용은 superset-fleet이고, herdr와 Orca용도 따로 있습니다(herdr-fleet, orca-fleet).

플러그인을 쓰면 Claude Code나 Codex 세션 하나가 작업을 나누고, 규칙대로 고른 프로필로 작업마다 워커를 띄웁니다. 그 뒤로는 워커를 지켜보며 질문에 답합니다. 결과를 검증한 뒤 정리하는 것까지가 플러그인의 몫입니다.

필요한 것 하나만 설치하고 요청하면 됩니다.

claude plugin marketplace add larcane97/clausona
claude plugin install superset-fleet@clausona   # herdr-fleet, orca-fleet도 같은 방식

Codex에서는 codex plugin marketplace add와 codex plugin add로 똑같이 설치하고, fleet-core@clausona도 함께 추가합니다.

"이 작업들을 Superset에서 내 계정들에 나눠 줘: notes list에 --json 옵션 추가, src/parse.ts 테스트 작성, docs/의 깨진 링크 수정."

서브에이전트로 부족한 점

서브에이전트는 한 세션 안에서 잠깐 맡기는 심부름용입니다. 그래서 실제 작업 여러 개를 동시에 돌리면 한계가 드러납니다.

  • 서브에이전트는 부모 세션 안에서 돌아갑니다. 돌려준 결과만 보이고 과정은 보이지 않아서, 엉뚱한 방향으로 가도 끝나야 알게 됩니다.
  • 서브에이전트 하나에 직접 입력해서 바로잡거나 질문에 답할 수 없습니다. 하나를 멈추려면 보통 전부를 돌리는 세션을 중단해야 합니다.
  • 서브에이전트는 자신을 띄운 세션의 계정으로 돌아갑니다. 다섯 개를 동시에 돌리면 그 계정의 5시간 한도가 다섯 배 빨리 닳습니다. 다른 계정이나 다른 회사의 모델로 돌릴 수도 없습니다.

반면 따로 띄운 세션은 다릅니다.

워커 하나하나가 평범한 Claude Code 세션이라서, 다른 워커는 건드리지 않고 하나만 골라 지켜볼 수 있습니다. 질문에 답하거나 멈추는 것도 그 세션에서 하면 돼요. Superset에서는 각 워커가 자기 탭과 worktree에서 돌아갑니다.

tmux, herdr, Orca, Superset과 함께 쓰기

herdr, Orca, Superset은 에이전트를 띄우고 보여 주는 쪽입니다. clausona는 에이전트를 지정한 계정이나 모델로 띄우는 쪽이고요.

그러니 둘을 함께 쓰면 됩니다.

어느 터미널이든 clausona run claude:work로 그 계정의 Claude Code 세션을 띄웁니다. 도구마다 다른 건 이 명령을 넣는 자리뿐이에요.

tmux에서는 새 창으로 띄우면 됩니다.

tmux new-window 'clausona run claude:work'

herdr는 에이전트 창을 유지하고 창마다 상태를 보여 주는 터미널 런타임입니다. 창을 하나 열고 그 안에서 clausona run claude:work를 실행하면 됩니다. herdr에서는 herdr-fleet 플러그인이 조율을 맡아요. 자세한 내용은 herdr 가이드에 있습니다.

Orca는 코딩 에이전트를 각자의 git worktree에서 나란히 돌리는 오픈소스 데스크톱 앱입니다. 어떤 CLI 에이전트든 실행할 수 있습니다. Orca 터미널에서 clausona run claude:work를 실행하면 그 계정으로 Claude Code가 뜹니다.

참고로 Orca에는 Claude와 Codex 계정을 바꾸는 자체 기능이 있습니다. Orca에서는 orca-fleet 플러그인이 조율을 맡고, 자세한 내용은 Orca 가이드에 있습니다.

Superset에서는 커스텀 에이전트로 등록합니다. command에는 command -v clausona가 출력하는 전체 경로를 넣고, arguments는 run claude:work -- --model claude-sonnet-5-5 --effort high --permission-mode acceptEdits --strict-mcp-config처럼 둡니다. 자세한 순서는 조율 스킬 설정하기에 있습니다.

조율 플러그인은 그 위에 다음 일을 더합니다.

  • 계획
  • 규칙과 사용량에 따른 배정
  • 지켜보기
  • 결과 검증
  • 워커 정리

여기부터는 Superset의 superset-fleet을 예로 들어 설명합니다. herdr와 Orca도 흐름은 같아요.

조율 스킬이 동작하는 방식

Superset 안의 Claude Code나 Codex 세션 하나와 대화합니다. 이 세션이 오케스트레이터입니다.

superset-fleet 스킬을 쓰는 오케스트레이터는 다음 순서로 일합니다.

  1. 작업마다 프로필을 고릅니다. 요청과 규칙을 따르되 프로필마다 남은 사용량도 봅니다. 그렇게 짠 계획을 먼저 보여 줍니다.
  2. 워커를 띄웁니다. 작업마다 Superset 워크스페이스를 하나씩 만들고, 이름에 작업과 프로필을 붙입니다. 그래서 사이드바만 봐도 어느 계정이 무엇을 하는지 보입니다.
  3. 워커를 지켜봅니다. 질문에 답하고, 권한 확인에서 멈춘 워커가 있으면 알려 줍니다. 그러다 계정이 한도에 걸리면 허용된 다른 프로필로 작업을 넘깁니다.
  4. 결과를 직접 검증합니다. 커밋과 diff를 보고, 브리프에 적힌 검사 명령도 직접 확인합니다. 보고할 때는 확인한 것과 워커가 주장만 한 것을 나눕니다.
  5. 끝난 워커를 정리합니다. 기본값은 물어본 뒤 정리하는 것입니다. 브랜치가 push되고 worktree가 깨끗할 때만 정리합니다. 브랜치는 그대로 남습니다.

시작 전에 보여 주는 계획은 이런 모양이에요.

작업프로필이유
notes list에 --jsonclaude:workOpus 5.5CLI 핵심 코드를 건드려서 규칙에 따라 여기로
src/parse.ts 테스트claude:deepseekdeepseek-v4-pro검사 명령이 있는 작고 분명한 작업
docs/ 깨진 링크claude:sideSonnet 5.5구독 프로필 중 여유가 가장 많음

에이전트마다 계정과 모델 정하기

세션을 손으로 띄울 때는 프로필도 손으로 고릅니다. 다섯 개쯤 되면 이것도 꽤 일이죠.

대신 스킬을 쓰면 이 선택을 규칙에 맡길 수 있습니다. 오케스트레이터가 따르는 순서는 이렇습니다.

  1. 대화에서 말한 것
  2. ~/.clausona/fleet.json(세 조율 플러그인이 함께 씁니다)
  3. 기본값
{
  "workers": ["claude:work", "claude:side", "claude:deepseek"],
  "routing": [
    "claude:deepseek는 테스트와 문서 수정만, src/ 아래는 고치지 않는다",
    "릴리스 과정에 닿는 작업은 claude:work로"
  ],
  "maxUsage": 80,
  "retire": "ask"
}
  • workers: 워커로 쓸 수 있는 프로필 목록입니다.
  • routing: 자연어로 적은 규칙입니다. 오케스트레이터가 계획을 채울 때 적용합니다.
  • maxUsage: 구독 프로필의 5시간 또는 주간 사용량이 이 퍼센트에 이르면 건너뜁니다. 기본값은 90입니다.
  • retire: ask(기본) 또는 auto입니다.
  • permissions: 워커의 권한 모드를 도구별로 정합니다. 예: {"claude": "acceptEdits", "codex": "on-request"}. Codex 기본 샌드박스에서는 Codex 워커가 커밋과 푸시 전에 매번 승인을 물어요. 알아서 하게 하려면 "codexSandbox": "danger-full-access"를 넣으면 됩니다. 이러면 워커의 Codex 샌드박스가 꺼집니다.

규칙이 정하지 않은 부분은 기본값을 따릅니다.

  • 오케스트레이터는 자기 프로필에는 워커를 띄우지 않습니다.
  • 워커는 오케스트레이터와 같은 도구의 계정을 씁니다. 다른 도구의 계정은 직접 지정하거나 workers에 넣었을 때만 써요.
  • 여유가 많은 프로필부터 쓰면서 워커를 고루 나눕니다.
  • 단순 반복 작업은 API 프로필에 맡깁니다.
  • 위험한 변경은 제3의 프로필에서 따로 검증합니다.

설정은 말로 바꿔도 됩니다. "claude:personal은 워커로 쓰지 마"처럼 요청하면 설정 파일이 바뀌어요.

DeepSeek 같은 API 모델 추가하기

워커가 꼭 구독 계정일 필요는 없습니다. Anthropic Messages 형식을 지원하는 엔드포인트라면 무엇이든 프로필이 됩니다.

DeepSeek는 https://api.deepseek.com/anthropic에서 이 형식을 제공합니다.

clausona add claude:deepseek --api \
  --base-url https://api.deepseek.com/anthropic \
  --model deepseek-v4-pro

키는 화면에 보이지 않게 입력받아, macOS 키체인이나 ~/.clausona/secrets.json에 보관합니다. 이 프로필도 다른 계정처럼 스킬과 플러그인을 공유합니다. hook도 마찬가지고요.

물론 OpenRouter 같은 게이트웨이나 직접 띄운 모델도 같은 방식으로 추가합니다.

다만 API 워커는 다루는 요령이 조금 다릅니다.

  • API 워커에는 작고 분명한 브리프를 주세요. 파일과 함수를 짚어 주고, 바꿀 내용과 확인할 명령까지 적습니다. 길고 탐색적인 브리프는 작은 컨텍스트 창에 다 들어가지 않거든요.
  • API 워커에는 --tools=Bash,Read,Edit,Write,Grep,Glob처럼 짧은 도구 목록을 주면 도구 정의가 컨텍스트를 덜 차지합니다.
  • 엔드포인트가 프롬프트 캐싱을 지원하는지 확인하세요. 지원하지 않으면 매 턴 대화 전체를 다시 읽어서 긴 세션이 느려집니다.

결국 선택지는 둘입니다. 서브에이전트에 맡기거나, clausona로 세션을 따로 띄우거나요.

다만 짧은 심부름이라면 솔직히 서브에이전트로 충분해요.

조율 스킬 설정하기

Superset에서 조율 스킬을 쓰려면 이렇게 준비합니다.

  1. clausona를 설치하고 계정이나 API 엔드포인트마다 프로필을 추가합니다.

    clausona add claude:work
clausona add claude:side

  2. Superset의 Settings > Agents에서 프로필마다 커스텀 에이전트를 추가합니다. Command에는 command -v clausona의 출력을, Arguments에는 예를 들어 다음을 넣습니다.

    run claude:work -- --model claude-sonnet-5-5 --effort high --permission-mode acceptEdits --strict-mcp-config

    Superset은 커스텀 에이전트에 모델과 effort를 넘기지 않거든요. 그래서 여기에 적습니다.

    --strict-mcp-config는 워커가 "new MCP servers found" 질문에서 멈추지 않게 합니다. Superset CLI에 로그인하지 않았다면 스킬이 물어본 뒤 직접 추가해 줍니다.

  3. 새 프로필은 한 번 직접 실행해서 첫 실행 질문에 미리 답해 둡니다.

    clausona run claude:deepseek

  4. 플러그인을 설치합니다. 플러그인은 프로필끼리 공유되므로 한 번이면 됩니다.

    claude plugin marketplace add larcane97/clausona
claude plugin install superset-fleet@clausona

조율 스킬에는 아직 한계가 있습니다.

  • Superset이 같은 컴퓨터에서 돌아가야 합니다.
  • Superset CLI 없이 쓸 때는 로컬 호스트 서비스를 거치는데, 이건 문서화된 API가 아닙니다. 그래서 업데이트로 바뀌면 헬퍼가 알리고 멈춥니다.

자주 묻는 질문

오케스트레이터가 자기 계정으로 워커를 띄우나요?

아니요. 오케스트레이터가 쓰는 프로필은 조율만 하고, 워커는 다른 프로필로 띄웁니다.

워커를 정리하다 작업이 날아갈 수 있나요?

작업이 검증된 뒤에만 정리합니다. 그때도 브랜치가 push되고 worktree가 깨끗해야 합니다. Superset에서는 스킬의 헬퍼가 워크스페이스를 지우기 직전에 브랜치와 worktree를 다시 확인하고, 하나라도 깨끗하지 않으면 거부합니다. herdr와 Orca는 커밋하지 않은 변경이 있는 worktree를 스스로 지우지 않습니다.

에이전트마다 다른 계정을 쓰려면 Superset이 꼭 필요한가요?

아니요. 어느 실행 환경이든 clausona run claude:work로 띄우면 그 계정으로 Claude Code가 돌아갑니다. Superset, herdr, Orca용 조율 플러그인은 그 위에 계획과 검증 같은 조율을 더할 뿐입니다.
