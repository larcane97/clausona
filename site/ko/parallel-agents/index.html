작업 하나를 다섯 갈래로 나눌 때 보통은 서브에이전트를 씁니다. 그런데 서브에이전트는 일하는 과정이 보이지 않고, 하나만 골라 끼어들기 어렵고, 다섯 개 모두 같은 계정을 씁니다. 여기서는 에이전트마다 지켜보고 끼어들 수 있는 독립된 Claude Code 세션을 띄우고, 각각을 정해 둔 계정이나 모델로 보내는 방법을 다룹니다. 회사 계정, 두 번째 구독 계정, DeepSeek 같은 API 모델 모두 가능합니다.

2026년 10월 8일 업데이트

짧은 답. Superset은 에이전트마다 git worktree와 탭을 따로 줍니다. clausona는 그 에이전트마다 계정이나 API 엔드포인트인 프로필을 줍니다. superset-fleet 스킬을 쓰면 Claude Code 세션 하나가 작업을 나누고, 규칙대로 고른 프로필로 작업마다 워커를 띄우고, 지켜보며 질문에 답하고, 결과를 검증한 뒤 정리까지 합니다. 스킬을 한 번 설치하고 요청하면 됩니다.

서브에이전트의 한계

서브에이전트는 한 세션 안에서 잠깐 맡기는 심부름에 맞게 만들어졌습니다. 실제 작업 여러 개를 동시에 돌리면 세 가지가 걸립니다.

  • 일하는 과정이 안 보입니다. 서브에이전트는 부모 세션 안에서 돕니다. 돌려준 결과만 보이고 과정은 보이지 않아서, 엉뚱한 방향으로 가도 끝나야 알게 됩니다.
  • 하나만 골라 끼어들 수 없습니다. 서브에이전트 하나에 직접 입력해서 바로잡거나 질문에 답할 수 없습니다. 하나를 멈추려면 보통 전부를 돌리는 세션을 중단해야 합니다.
  • 모두 한 계정을 씁니다. 서브에이전트는 자신을 띄운 세션의 계정으로 돕니다. 다섯 개를 동시에 돌리면 그 계정의 5시간 한도가 다섯 배 빨리 닳고, 다른 계정이나 다른 회사의 모델로는 돌릴 수 없습니다.

Superset에서는 워커 하나하나가 각자의 탭과 worktree에서 도는 평범한 Claude Code 세션입니다. 다른 워커는 건드리지 않고 하나만 골라 지켜보거나, 질문에 답하거나, 멈출 수 있습니다.

fleet이 동작하는 방식

Superset 안의 Claude Code 세션 하나, 즉 오케스트레이터와 대화합니다. superset-fleet 스킬을 쓰는 오케스트레이터는 다음 순서로 일합니다.

  1. 작업마다 프로필을 고릅니다. 요청, 규칙, 프로필마다 현재 사용량을 보고 계획을 보여 줍니다.
  2. 워커를 띄웁니다. 작업마다 Superset 워크스페이스를 하나씩 만들고, 작업과 프로필 이름을 붙여서 사이드바에서 어느 계정이 무엇을 하는지 보이게 합니다.
  3. 지켜봅니다. 워커의 질문에 답하고, 권한 확인에서 멈춘 워커가 있으면 알려 주고, 계정이 한도에 닿으면 허용된 다른 프로필로 작업을 넘깁니다.
  4. 결과를 직접 검증합니다. 커밋, diff, 브리프에 적힌 검사 명령을 직접 확인하고, 확인한 것과 워커가 주장만 한 것을 나눠 보고합니다.
  5. 끝난 워커를 정리합니다. 기본은 물어본 뒤 정리합니다. 브랜치가 push되고 worktree가 깨끗할 때만 정리하며, 브랜치는 남습니다.

시작 전에 보여 주는 계획의 예입니다.

작업프로필이유
notes list에 --jsonclaude:workOpus 5.5CLI 핵심을 건드림, 규칙상 여기로
src/parse.ts 테스트claude:deepseekdeepseek-v4-pro검사 명령이 있는 작고 분명한 작업
docs/ 깨진 링크claude:sideSonnet 5.5구독 프로필 중 여유가 가장 많음

에이전트마다 계정·모델 정하기

에이전트를 터미널에 여러 개 띄우는 것만으로는 해 주지 않는 부분입니다. 오케스트레이터는 대화에서 말한 것, ~/.clausona/superset-fleet.json, 기본값 순서로 따릅니다.

{
  "workers": ["claude:work", "claude:side", "claude:deepseek"],
  "routing": [
    "claude:deepseek는 테스트와 문서 수정만, src/ 아래는 고치지 않는다",
    "릴리스 과정에 닿는 작업은 claude:work로"
  ],
  "maxUsage": 80,
  "retire": "ask"
}
  • workers: 워커로 쓸 수 있는 프로필 목록입니다.
  • routing: 평범한 말로 적은 나만의 규칙입니다. 오케스트레이터가 계획을 채울 때 적용합니다.
  • maxUsage: 구독 프로필의 5시간 또는 주간 사용량이 이 퍼센트에 닿으면 건너뜁니다. 기본값은 90입니다.
  • retire: ask(기본) 또는 auto입니다.

규칙이 정하지 않은 부분은 기본값을 따릅니다. 오케스트레이터 자신의 프로필에는 워커를 띄우지 않고, 여유가 많은 프로필을 우선하며 워커를 고루 나누고, 단순 반복 작업은 API 프로필로 보내고, 위험한 변경의 독립 검증은 제3의 프로필에서 돌립니다. "claude:personal은 워커로 쓰지 마"처럼 말로 요청해도 파일이 바뀝니다.

DeepSeek 같은 API 모델 추가하기

Anthropic Messages 형식을 지원하는 엔드포인트라면 무엇이든 프로필이 됩니다. DeepSeek은 https://api.deepseek.com/anthropic에서 제공합니다.

clausona add claude:deepseek --api \
  --base-url https://api.deepseek.com/anthropic \
  --model deepseek-v4-pro

키는 화면에 보이지 않게 입력받아 macOS 키체인이나 ~/.clausona/secrets.json에 보관합니다. 이 프로필도 다른 계정처럼 스킬, 훅, 플러그인을 공유합니다. OpenRouter, 게이트웨이, 직접 띄운 모델도 같은 방식입니다.

  • API 워커에는 작고 분명한 브리프를 주세요. 파일, 함수, 바꿀 내용, 확인할 명령까지 적습니다. 길고 탐색적인 브리프는 작은 컨텍스트를 넘칩니다.
  • Superset 에이전트 설정에 --tools=Bash,Read,Edit,Write,Grep,Glob처럼 짧은 도구 목록을 주면 도구 정의가 컨텍스트를 덜 차지합니다.
  • 엔드포인트가 프롬프트 캐싱을 지원하는지 확인하세요. 지원하지 않으면 매 턴 대화 전체를 다시 읽어서 긴 세션이 느려집니다.

서브에이전트, herdr와 비교

herdr는 코딩 에이전트용 터미널 런타임입니다. 에이전트 창을 백그라운드에서 유지하고, 창마다 작업 중·막힘·대기 상태를 표시하며, 에이전트끼리 창을 열고 서로 요청할 수 있게 해 줍니다. 다만 에이전트가 어느 계정이나 모델로 돌지는 정하지 않습니다. 창에서 실행한 명령이 그대로 돌 뿐입니다. clausona가 채우는 부분이 바로 이것이고, 둘을 함께 쓸 수도 있습니다. herdr 창에서 clausona run claude:work로 시작하면 그 계정으로 돕니다.

설정하기

  1. clausona를 설치하고 계정이나 API 엔드포인트마다 프로필을 추가합니다.

    clausona add claude:work
clausona add claude:side

  2. Superset → Settings → Agents에서 프로필마다 커스텀 에이전트를 추가합니다. Command에는 command -v clausona의 출력을, Arguments에는 예를 들어 다음을 넣습니다.

    run claude:work -- --model claude-sonnet-5-5 --effort high --permission-mode acceptEdits --strict-mcp-config

    Superset은 커스텀 에이전트에 모델과 effort를 넘기지 않으므로 여기에 적습니다. --strict-mcp-config는 워커가 "new MCP servers found" 질문에서 멈추지 않게 합니다. Superset CLI에 로그인하지 않았다면 스킬이 물어본 뒤 직접 추가해 줍니다.

  3. 새 프로필은 한 번 직접 실행해서 첫 실행 질문에 미리 답해 둡니다.

    clausona run claude:deepseek

  4. 플러그인을 설치합니다. 플러그인은 프로필끼리 공유되므로 한 번이면 됩니다.

    claude plugin marketplace add larcane97/clausona
claude plugin install clausona@clausona

제약도 있습니다. 워커는 Claude Code 세션만 지원하고 Codex 워커는 아직입니다. Superset이 같은 컴퓨터에서 돌아야 합니다. Superset CLI 없이 쓸 때 쓰는 로컬 호스트 서비스는 문서화된 API가 아니어서, 업데이트로 바뀌면 헬퍼가 알리고 멈춥니다.

자주 묻는 질문

오케스트레이터가 자기 계정으로 워커를 띄우나요?

아니요. 오케스트레이터가 쓰는 프로필은 조율만 하고, 워커는 다른 프로필로 띄웁니다.

워커를 정리하다 작업이 날아갈 수 있나요?

작업이 검증되고, 브랜치가 push되고, worktree가 깨끗할 때만 정리합니다. 스킬의 헬퍼가 워크스페이스를 지우기 직전에 브랜치와 worktree를 다시 확인하고, 하나라도 깨끗하지 않으면 거부합니다.

에이전트마다 다른 계정을 쓰려면 Superset이 꼭 필요한가요?

아니요. clausona run claude:work는 어느 터미널, tmux, herdr 창에서든 그 계정으로 Claude Code를 띄웁니다. Superset과 스킬은 그 위에 조율을 더합니다. 계획, 배정, 지켜보기, 검증입니다.

작업 중 계정이 한도에 닿으면 어떻게 되나요?

오케스트레이터가 규칙이 허용하는 다른 프로필로 같은 워크스페이스에서 작업을 넘기고, 멈춘 워커의 터미널을 닫습니다.
