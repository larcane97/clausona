How to use multiple Claude Code accounts on one machine

Claude Code signs in one account per config directory. Here is how to keep a work and a personal account side by side without setting up your skills, hooks and plugins twice, and how to share conversation history between them too.

Updated October 8, 2026

Short answer. Give each account its own config directory with CLAUDE_CONFIG_DIR, and link everything except the sign-in back to your main ~/.claude. clausona does that in three commands:

clausona init              # register the account already signed in
clausona add claude:work   # a second account, with Claude Code's own sign-in
csn use work               # plain `claude` now starts as that account

Why a second account is awkward

Claude Code keeps one signed-in account at a time. Switching with /logout and /login works, but every switch means signing in again, and one terminal can't stay on your work account while another uses your personal one.

The CLAUDE_CONFIG_DIR environment variable moves Claude Code's whole config directory, so a second directory can hold a second sign-in. The catch is that the new directory starts empty: no settings, no hooks, no skills, no plugins, no CLAUDE.md and no history. Install a plugin under one account and the other doesn't have it, and the two setups drift apart from there.

Option 1: CLAUDE_CONFIG_DIR by hand

Keep ~/.claude as your main directory, give the second account a directory of its own, and link into it whatever both accounts should share:

# a directory for the second account
mkdir -p ~/.claude-work

# link what both accounts should share
for item in settings.json CLAUDE.md skills commands agents hooks; do
  [ -e ~/.claude/$item ] && ln -sn ~/.claude/$item ~/.claude-work/$item
done

# start Claude Code there and sign in with the second account
CLAUDE_CONFIG_DIR=~/.claude-work claude

Hooks are configured in settings.json, so linking it shares them, along with your permissions, status line and model choice. The hooks link covers scripts you keep in ~/.claude/hooks. Then add an alias for the second account:

alias claude-work='CLAUDE_CONFIG_DIR=~/.claude-work claude'

Leave CLAUDE_CONFIG_DIR unset for your main account. Claude Code treats any value as a separate directory, even ~/.claude: with the variable set it reads ~/.claude/.claude.json instead of ~/.claude.json, and on macOS it looks for a different Keychain item, so you land in a second, signed-out identity. (Checked with Claude Code 2.1.278 on macOS.)

What must not be shared

  • .claude.json records which account is signed in, along with the MCP servers added with claude mcp add. Linking it mixes up which account each directory belongs to. To have an MCP server under both accounts, add it to each, or put it in a project's .mcp.json.
  • .credentials.json holds the sign-in tokens on Linux and Windows, and on macOS when the Keychain refuses them. On macOS the tokens normally sit in the Keychain under a name derived from the config directory, so each directory gets its own.
  • plugins/ as a whole. Two files in it, known_marketplaces.json and installed_plugins.json, store absolute paths into the config directory. Link the rest of plugins/, keep a copy of those two in each directory with the paths pointing at that directory, and update the copies whenever you add or remove a plugin.
  • Small per-directory state, such as .last-update-result.json, which Claude Code rewrites as a new file and which describes one directory only.

Newer Claude Code versions also add directories. A link you made today doesn't cover a directory that appears next month, so the second account quietly gets its own copy. Check your links after updating Claude Code.

Option 2: clausona

clausona is a free, open-source CLI that does the steps above and keeps them correct. Install it:

macOS and Linux curl -fsSL https://github.com/larcane97/clausona/releases/latest/download/install.sh | bash
Windows PowerShell irm https://github.com/larcane97/clausona/releases/latest/download/install.ps1 | iex

Then register the account you're signed in to, and add the others:

clausona init              # registers the accounts already signed in
clausona add claude:work   # makes ~/.claude-work and opens Claude Code's sign-in
csn use work               # plain `claude` now starts as the work account
csn use claude:default     # back to the first account; init names it default

Each account gets its own directory. Everything in ~/.claude except the sign-in, the account file, per-directory state and, unless you merge sessions, conversation history is linked into it, so settings, hooks, skills, commands, agents, plugins and CLAUDE.md are the same under every account. clausona keeps the two plugin files in step for each account, and clausona doctor reports a directory a newer Claude Code added that isn't linked yet; clausona repair <profile> links it. csn is the short name for clausona.

There is no wrapper around Claude Code: a shell hook sets CLAUDE_CONFIG_DIR for each run and starts the real claude, and nothing stays running in the background.

Share conversation history between accounts

Conversation history lives in projects/, next to two directories that refer to it by session id: jobs/ for background sessions and teams/. Share all three or none of them. A background session whose record and transcript sit in different directories can't be resumed.

With clausona it is one switch per account:

clausona config claude:work --merge-sessions

Turning it on copies the account's existing conversations into the shared history first, so none are lost. From then on, claude --resume lists conversations from every account that shares history, claude --continue picks up the latest one in the current folder whichever account started it, and a /goal set in that conversation comes back with it. --separate-sessions turns it off. You can also pass --merge-sessions to clausona add or clausona init.

Use two accounts at the same time

csn use sets which account new claude launches use. To run one session under another account without changing that, start it with clausona run:

clausona run claude:work

One terminal can stay on your main account while another runs the work one, both with the same skills and hooks. Arguments after -- go to Claude Code.

See how much each account has left

clausona list shows every account's 5-hour and weekly limits, read from Claude Code's own usage endpoint with the credential Claude Code stored for that account:

PROFILE             ACCOUNT              5H         7D
claude:work         dev@example.com      62% 1h     41% 3d
claude:personal     me@example.org       8%         77% 5d

Running csn with no arguments opens a dashboard with the same readings and the exact reset times.

Questions

Can I be signed in to two Claude Code accounts at once?

Yes, with one config directory per account. Two terminals with different CLAUDE_CONFIG_DIR values run two accounts side by side. clausona run claude:work starts one session under another account without changing the default.

Do MCP servers carry over to the other account?

Servers that come with a plugin do, because plugins are shared. Servers added with claude mcp add are stored in .claude.json next to the account's sign-in, which must not be shared, so add them to each account or put them in a project's .mcp.json.

Does clausona switch accounts automatically when I hit a limit?

No. You choose the account for each terminal; clausona shows how much of each account's limits is left. Keep each account to what it's for, such as work and personal use, and within Anthropic's terms.

Is my sign-in ever shared?

No. Each account keeps its own credentials and its own .claude.json.

Does it work with tools that start Claude Code themselves?

The shell hook covers claude started from your shell. A tool that starts Claude Code on its own, such as Superset, can use clausona run claude:work -- <args> as its command to run on that account.

Can a profile use an API key or another model?

Yes. clausona add claude:gw --api --base-url <url> adds a profile for the Anthropic API, a gateway such as OpenRouter, or a model you serve yourself. It shares the same setup and switches like any account.

Does it work on Windows?

Yes, in PowerShell 5.1 or later. Shared directories are junctions. Turn on Developer Mode: without it, settings.json, CLAUDE.md and keybindings.json stay a per-account copy, because Claude Code replaces them on every save, and clausona doctor says so.
