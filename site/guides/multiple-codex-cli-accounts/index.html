How to use multiple Codex CLI accounts on one machine

Codex CLI keeps its sign-in and everything else in one home directory, ~/.codex. Give each account its own home and you can switch without logging out. Share the right files and every account has the same config, hooks and skills; share the wrong ones and one account's daemon or memories end up serving another.

Updated October 8, 2026

Short answer. Run each account with its own CODEX_HOME, and link only the configuration back to ~/.codex: config.toml, hooks.json, AGENTS.md, rules/, skills/, plugins/, agents/ and prompts/. clausona does that in three commands:

clausona init              # register the homes already signed in
clausona add codex:work    # a second account, with Codex's own login
csn use codex:work         # plain `codex` now starts as that account

Option 1: CODEX_HOME by hand

Logging out and in replaces the one auth.json each time, and two accounts can't run at once. CODEX_HOME tells Codex which home to use, so each account can have its own. Keep ~/.codex as the main one and link the configuration into the second:

# a home for the second account
mkdir -p ~/.codex-work

# link the configuration both accounts should share
for item in config.toml hooks.json AGENTS.md rules skills plugins agents prompts; do
  [ -e ~/.codex/$item ] && ln -sn ~/.codex/$item ~/.codex-work/$item
done

# sign in to the second account in its own home
CODEX_HOME=~/.codex-work codex login

config.toml holds your MCP servers and Codex profiles, so they're shared too. Then add an alias:

alias codex-work='CODEX_HOME=~/.codex-work codex'

Keep the home's path short. Codex's app-server daemon puts a Unix socket inside CODEX_HOME, and a socket path can be only about 100 bytes long on macOS and Linux. Under a deep path, the daemon's auto-update stops without saying so. ~/.codex-work is fine.

What must stay with each account

Codex keeps more than configuration in its home, and each release adds a little more. These belong to one account (checked with Codex CLI 0.159):

  • auth.json is the sign-in. .credentials.json and secrets/ hold other tokens.
  • app-server-control/ and app-server-daemon/. Codex starts a background app-server daemon and finds it through app-server-control/. A home that links the main one's talks to the main account's daemon, so Codex runs on the wrong account, and stopping the daemon in one home stops the other's.
  • memories/ and memories_1.sqlite hold summaries of past conversations that Codex adds to future prompts. Shared, one account's conversations reach the other account's prompts.
  • The other SQLite databases, with their -wal and -shm files: queues, logs and state for one account.
  • .env. Codex loads it into its environment at start, so it may hold one account's API keys.
  • packages/ is the daemon's own install, about 300 MB. Shared, one updater would replace the daemon every home runs.

That is why it pays to share by a list of what to share, as above, rather than linking the whole home and leaving a few files out. A file a new Codex version adds then stays with its account until you decide otherwise.

Option 2: clausona

clausona is a free, open-source CLI that sets up each account's home this way, for Codex CLI and Claude Code. Install it:

macOS and Linux curl -fsSL https://github.com/larcane97/clausona/releases/latest/download/install.sh | bash
Windows PowerShell irm https://github.com/larcane97/clausona/releases/latest/download/install.ps1 | iex

Sign in to Codex once as usual, then:

clausona init              # registers ~/.codex and other homes already signed in
clausona add codex:work    # makes ~/.codex-work and runs Codex's own login
csn use codex:work         # plain `codex` now starts as the work account

clausona links only the entries on its list into each home, and keeps the rest with the account. clausona doctor reports a home set up by an older version that still links account state, such as the daemon's directories or memories, and clausona repair <profile> unlinks it and puts the account's own copy back from a backup. Nothing is deleted along the way. csn is the short name for clausona.

There is no wrapper around Codex: a shell hook sets CODEX_HOME for each run and starts the real codex.

Resume conversations across accounts

Codex keeps conversations in sessions/, with history.jsonl and session_index.jsonl beside them. It finds threads through state_5.sqlite, keeps each thread's /goal in goals_1.sqlite, and indexes the conversation files in thread_history_1.sqlite. Resuming under another account needs all of these shared together. The databases need care: link only the database file, never its -wal or -shm, because SQLite keeps those beside the file the link leads to.

With clausona it is one switch per account. Quit Codex in that account first and stop its daemon (CODEX_HOME=~/.codex-work codex app-server daemon stop); on macOS and Linux clausona refuses to move files while either is running.

clausona config codex:work --merge-sessions

From then on, on macOS and Linux, codex resume and codex resume --last find threads from every account that shares history, and a resumed thread's goal comes back with it. Unlike Claude Code, the account's earlier Codex conversations aren't copied into the shared history: they're set aside in ~/.clausona/backups/codex/<profile>/ and come back with --separate-sessions. Memories still stay with each account. On Windows the thread store stays per account, because SQLite there names its log after the path it was opened by, so a thread from another account is resumed by its id.

Two accounts at once, and usage for each

csn use codex:work sets which account new codex launches use. To run one session under another account without changing that:

clausona run codex:default

clausona list shows each account's 5-hour and weekly limits, read from Codex's own usage endpoint with that account's stored login, next to your Claude Code accounts.

Questions

How do I switch Codex CLI accounts without logging out?

Give each account its own CODEX_HOME and sign in to each once with CODEX_HOME=<dir> codex login. Codex starts as whichever account's home it is pointed at. With clausona: clausona add codex:work, then csn use codex:work.

Which files in ~/.codex can be shared between accounts?

The configuration: config.toml and any *.config.toml, hooks.json, AGENTS.md, rules/, skills/, plugins/, agents/ and prompts/. Keep auth.json, the app-server daemon's directories, memories, the databases, .env and packages/ with each account.

Why not share the whole ~/.codex directory?

Codex keeps account state in its home. A shared app-server-control/ makes Codex talk to another account's daemon and run on that account, and shared memories put one account's past conversations into another account's prompts.

Are Codex and Claude Code setups shared with each other?

No. Codex accounts share ~/.codex's configuration, and Claude Code accounts share ~/.claude's. The two tools stay separate.

Does clausona switch accounts when one reaches its limit?

No. You choose the account for each terminal; clausona shows how much of each account's limits is left.

What if I already set CODEX_HOME myself?

clausona steps aside in that shell, and Codex uses the home you set.
