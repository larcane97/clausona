Claude Code account switchers compared

Running a work account alongside a personal one gets old when you have to sign out to switch. Several tools handle this now, and they take different approaches under the hood.

Updated November 9, 2026

When you only need one account active at a time, a sign-in swapper keeps a single setup, and claude-swap lets a running session follow the switch. To keep two accounts open at once on the same setup, use a tool that gives each account its own config directory, like clausona or ccam. For Codex CLI, clausona and aisw support it alongside Claude Code, while codex-auth targets Codex alone.

Swap one sign-in

Most switchers take this approach. Claude Code keeps one sign-in per config directory, so the tool keeps a saved copy for each account and writes the one you pick into place when you switch.

Everything else stays in that single folder. Because both accounts read the same settings and history, your two setups never drift apart.

The trade-off is that you can only use one account at a time. Every terminal and editor on the machine shares that active sign-in.

Active sessions behave differently depending on the tool. According to claude-swap, a running session picks up the new account on the next message on Linux and Windows, or within about 30 seconds on macOS. ClaudeCodeMultiAccounts waits until every Claude Code window closes before switching, while aisw and codex-auth require starting a new session.

Saved credentials also have to stay valid while Claude Code renews tokens in the background. The claude-swap README warns that running /logout may revoke the stored refresh token for the account you leave. To avoid writing in the middle of a token refresh, claude-swap acquires Claude Code's own credential locks during a switch.

Running /logout and /login does the same thing without an extra tool. You just have to go through the browser sign-in flow every time you switch.

A directory per account

Claude Code documents this method directly. Point CLAUDE_CONFIG_DIR at a separate folder for each account, and each folder holds its own sign-in. Codex works the same way with CODEX_HOME.

Both accounts stay signed in at once. You can run a work session in one terminal and a personal session in another, and Claude Code renews each token inside its own directory.

The catch is that a fresh directory starts empty. None of your settings, skills, plugins or history exist there until you symlink them from your main directory, and a Claude Code update can add a new folder that your links miss. The Claude Code guide covers setting those links up by hand.

Tools built around this model differ in what they link for you.

clausona links everything from your main directory except the sign-in and account-specific state. If a Claude Code update adds an unlinked folder, clausona doctor flags it. Conversation history stays separate per account until you turn on sharing.

ccam organizes accounts into groups. Each group defines what to share, like MCP servers or history, so two work accounts can share history while a personal account stays separate.

In claude-swap, cswap run links settings, CLAUDE.md, skills, commands and agents from ~/.claude, while sharing history by default. It leaves plugins out.

aisw defaults to isolated mode, giving each profile its own directory without sharing files between them.

MCP servers added via claude mcp add are written to .claude.json alongside account-specific state, so that file cannot be symlinked across accounts. clausona leaves those servers per account. ccam passes shared servers at launch using --mcp-config, while claude-swap copies them in on each run.

An app that launches agents

Orca is a desktop app for running coding agents side by side. Its status bar includes an account switcher for Claude Code and Codex that displays usage for each account.

Selecting an account in the status bar applies to the next agent Orca launches. Any session already running stays on the account it started with.

That switcher only affects sessions inside Orca. Codex accounts added in Orca use their own home directories and leave ~/.codex untouched, so running codex in an outside terminal still uses the ~/.codex sign-in.

If you already launch all your agents from Orca, its built-in switcher may cover what you need. You can also use clausona inside an Orca terminal: running clausona run claude:work starts Claude Code on that account, and the Orca guide walks through running a fleet there.

When clausona isn't the right pick

Because this is clausona's site, it is worth being direct about when another tool fits your setup.

If you only switch once a week and never run both accounts at the same time, /logout and /login handles it without installing anything.

If you want an active session to switch accounts mid-run when usage runs low, clausona won't do that. Its dynamic routing picks an account only when a run starts, and a running session never moves. Instead, claude-swap's cswap auto swaps the active sign-in at a usage threshold while Claude Code is running, and ccam can move a session after Claude Code hits a limit if auto_switch is enabled.

If you don't want Node.js on the machine, skip clausona, which requires Node.js 20 or later. ccam ships as a single Go binary, and aisw installs via Homebrew or cargo.

If you are on Windows and want zero new dependencies, the PowerShell steps in the Claude Code guide set up a second account using directory junctions and a shell function.

If you also switch accounts in Gemini CLI or Antigravity, aisw supports both alongside Claude Code and Codex.

If you only use Codex and also work in the Codex App or the VS Code extension, codex-auth lists both alongside the CLI.

Keep the accounts to what they're for, such as work and personal use, within Anthropic's and OpenAI's terms.

Questions

What is the best Claude Code account switcher?

That comes down to how you run your accounts. For using one account at a time where an open session follows the switch, look at claude-swap. For running two accounts side by side on a shared setup, clausona and ccam each give every account its own config directory. If Codex CLI is part of your workflow too, clausona and aisw handle both tools, while switching once a week only takes /logout and /login.

Can I keep the same conversation when I switch accounts?

Yes, provided both accounts read from the same session history. Tools that swap credentials inside a single ~/.claude folder share one history automatically, and claude-swap states that an active session can continue right after a switch. When each account has its own config directory, history stays separate unless you share it. In clausona, running clausona config claude:work --merge-sessions links session history so claude --continue resumes the latest conversation in that project regardless of which account started it. In ccam, accounts in a group can share history, and ccam next --continue resumes the conversation on the next account.

Can two Claude Code accounts run at the same time?

Yes, by giving each account its own config directory, as described in Claude Code's docs. You can launch an isolated session in one terminal with clausona run claude:work or ccam <name>, and claude-swap offers cswap run for the same purpose without touching other open terminals. With ccswitch, you can export an account per shell after generating a token via claude setup-token. Tools that only overwrite the main sign-in file limit you to one active account at a time.

Do any of these work for Codex CLI too?

clausona supports Codex CLI by setting a separate CODEX_HOME per account through the same shell hook, and clausona list reports Codex usage alongside Claude Code. aisw handles both Codex and Claude Code as well as Gemini CLI and Antigravity. For a Codex-only tool, codex-auth swaps the account's auth.json into ~/.codex, while Orca switches Codex accounts for the agents it launches. The docs for claude-swap, ccam, ClaudeCodeMultiAccounts and ccswitch do not mention Codex.

Will a switcher move my session when an account runs low?

A couple of them do. In claude-swap, cswap auto swaps the sign-in when the active account hits a usage threshold (90% by default), and the running session continues on the new account. On Linux and macOS, ccam can move a session after Claude Code stops at its limit when auto_switch is enabled. clausona never moves a running session; instead, its dynamic routing selects an account with remaining usage at launch when you run clausona run --route main.
