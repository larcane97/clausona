Multiple Claude Code and Codex accounts, one shared setup

clausona gives each account its own sign-in and keeps the rest in one place. Skills, hooks, plugins and settings are shared by every account, and conversation history can be shared too.

clausona is a shell hook and a few symbolic links, and claude starts as fast as it does without it.

macOS and Linux curl -fsSL https://github.com/larcane97/clausona/releases/latest/download/install.sh | bash
Windows PowerShell irm https://github.com/larcane97/clausona/releases/latest/download/install.ps1 | iex

Needs Node.js 20 or later, and Claude Code or Codex CLI. Free and open source (MIT).

What each account keeps, and what they share

Claude Code and Codex CLI both keep everything in one directory: ~/.claude and ~/.codex. A second account normally means a second directory that starts empty. clausona gives every account its own directory for the sign-in and links the rest back to your main one, so you set things up once.

Codex keeps its memories, its app-server daemon and its databases with each account. Merging sessions shares only the conversation history and, on macOS and Linux, the thread store that indexes it, so one account's memories never reach another account's prompts.

A shell hook and a few symbolic links

clausona sets up the account before the tool starts and has no part in the session after that. There is no app to keep open and no service left running.

What starts with claude
The shell reads a cached launch script and runs the real binary. On an M4 Pro Mac, claude --version took a median 25 ms with the hook and 25 ms without it (Claude Code 2.1.294, 15 runs each).
When clausona itself runs
Only after you change something, such as csn use or a plugin install. Starting clausona takes about a third of a second, which is why ordinary launches skip it.
What it installs
One JavaScript file of about 1 MB, a hook in your shell's rc file, and a symbolic link for each shared file or folder. Updates are checked against the release's SHA-256 before they replace anything.
How to remove it
clausona uninstall takes out the hook, the links and ~/.clausona, keeping any backups that still hold data. Each account's directory and history stay where they are.

What it looks like

The recording lists the accounts with their plan usage, switches to the work account so that plain claude starts signed in as it, switches back, and opens the dashboard.

Pick up a conversation under another account

History is kept per account unless you ask for it to be shared. Merge sessions for an account and it shares conversation history with your main directory: claude --resume lists the conversations from every account that shares it, and claude --continue carries on the latest one in this folder, whichever account started it.

clausona config claude:personal --merge-sessions
csn use claude:personal
claude --continue    # the latest conversation in this folder

Codex works the same way on macOS and Linux: codex resume and codex resume --last find threads from every account that shares history, goals included. On Windows Codex's thread store stays with each account, so a thread from another account is resumed by its id.

Set up in three commands

  1. Register the accounts already signed in on this machine.

    clausona init

  2. Add another account. Claude Code's own sign-in opens for it.

    clausona add claude:work

  3. Choose the account. Plain claude now starts signed in as it, with the same skills, hooks and plugins.

    csn use work

Also in clausona

Two accounts at once
clausona run claude:personal starts one session under another account without switching, so two terminals can run two accounts side by side.
Usage for every account
clausona list and the dashboard show each account's 5-hour and weekly limits side by side, with the time until each resets.
API profiles
A Claude Code profile can use the Anthropic API, a gateway such as OpenRouter, or a model you serve yourself, and switches like any account.

Questions

Can I use two Claude Code accounts on one machine?

Yes. Claude Code keeps one sign-in per config directory. clausona gives each account its own directory and links skills, hooks, plugins and settings back to your main ~/.claude, so every account has the same setup. clausona add claude:work adds an account and csn use work switches to it.

Can I continue a conversation under another account?

Yes, once the accounts share history: clausona config <profile> --merge-sessions. Then claude --resume and claude --continue see conversations from every account that shares it, and so does codex resume on macOS and Linux.

Is my sign-in shared between accounts?

No. Each account keeps its own credentials. MCP servers added with claude mcp add live next to the sign-in, so they stay with the account too.

Does clausona switch accounts when one reaches its limit?

No. You choose which account each terminal uses. clausona shows how much of every account's limits is left.

Does it proxy or modify claude and codex?

No. The real binaries run unmodified, with the account's config directory set for that one run. If you set CLAUDE_CONFIG_DIR or CODEX_HOME yourself, clausona steps aside in that shell.

What does clausona send over the network?

clausona has no server and no telemetry. It reads each account's plan usage from that account's own provider, renewing a lapsed sign-in token when it has to, and the dashboard asks GitHub whether a newer clausona release is out.
