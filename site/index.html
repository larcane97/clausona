Multiple Claude Code and Codex accounts, one shared setup

You're signed in to Claude Code at work and want your personal account in the next terminal. clausona keeps the two sign-ins apart and lets them share one set of skills, hooks, plugins and settings. They can share conversation history too.

It's a shell hook and a few symbolic links. claude starts as fast as it does without it.

macOS and Linux curl -fsSL https://github.com/larcane97/clausona/releases/latest/download/install.sh | bash
Windows PowerShell irm https://github.com/larcane97/clausona/releases/latest/download/install.ps1 | iex

Needs Node.js 20 or later, and Claude Code or Codex CLI. Free and open source (MIT).

What's shared, and what stays with the account

Claude Code keeps everything in one directory, ~/.claude. Codex CLI does the same with ~/.codex.

A second account normally means a second directory that starts empty.

I've been using Claude Code with a personal and a work account, and I got tired of setting up plugins and permissions for both. So I made a simple tool for it.

clausona gives every account a directory for its sign-in. It links the rest back to your main one, so you set things up once.

Codex keeps memories with the account. Its app-server daemon and databases stay there too.

Merging sessions shares only the conversation history. On macOS and Linux, it also shares the thread store that indexes it.

So one account's memories never reach another account's prompts.

A shell hook and a few symbolic links

clausona sets up the account before the tool starts. After that, it has no part in the session.

There's no app to keep open and no service left running.

What starts with claude
The shell reads a cached launch script and runs the real binary. On an M4 Pro Mac, claude --version took a median 25 ms with the hook and 25 ms without it (Claude Code 2.1.294, 15 runs each).
When clausona itself runs
Only after you change something, such as csn use or a plugin install. Starting clausona takes about a third of a second. That's why ordinary launches skip it.
What it installs
One JavaScript file of about 1 MB, a hook in your shell's rc file, and symbolic links for the shared files and folders. Updates are checked against the release's SHA-256 before they replace anything.
How to remove it
clausona uninstall takes out the hook, the links and ~/.clausona. It keeps any backups that still hold data. Account directories and their history stay where they are.

What it looks like

The recording lists the accounts with their plan usage. Then it switches to the work account, so plain claude starts signed in as it.

It switches back and opens the dashboard.

Pick up a conversation under another account

History stays with the account unless you ask to share it.

Merge sessions for an account, and its conversation history is shared with your main directory.

claude --resume then lists conversations from all the accounts that share it.

claude --continue carries on the latest one in this folder, whichever account started it.

clausona config claude:personal --merge-sessions
csn use claude:personal
claude --continue    # the latest conversation in this folder

Codex works the same way on macOS and Linux. codex resume and codex resume --last find threads from the accounts that share history, goals included.

On Windows, Codex's thread store stays with the account. A thread from another account is resumed by its id.

Set up in three commands

  1. Register the accounts already signed in on this machine.

    clausona init

  2. Add another account. Claude Code's usual sign-in opens for it.

    clausona add claude:work

  3. Pick the account. Plain claude now starts signed in as it, on the same setup.

    csn use work

Questions

Can I use two Claude Code accounts on one machine?

Yes. Claude Code keeps one sign-in per config directory. clausona gives every account a directory and links skills, hooks, plugins and settings back to your main ~/.claude, so you set them up once. clausona add claude:work adds an account, and csn use work switches to it.

Can I continue a conversation under another account?

Yes, once the accounts share history. Turn that on with clausona config <profile> --merge-sessions. Then claude --resume and claude --continue see conversations from all the accounts that share it. So does codex resume on macOS and Linux.

Is my sign-in shared between accounts?

No. Credentials stay with their account. MCP servers added with claude mcp add live next to the sign-in, so they stay with the account too.

Does clausona switch accounts when one reaches its limit?

No. You choose the account a terminal uses. clausona shows how much of your accounts' limits is left.

Does it proxy or modify claude and codex?

No. The real binaries run unmodified, with the account's config directory set for that one run. If you set CLAUDE_CONFIG_DIR or CODEX_HOME yourself, clausona steps aside in that shell.

What does clausona send over the network?

clausona has no server and no telemetry. It reads an account's plan usage from that account's provider, and it renews a lapsed sign-in token when it has to. The dashboard also asks GitHub whether a newer clausona release is out.
