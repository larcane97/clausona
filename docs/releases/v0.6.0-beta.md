This release lets clausona pick the account for you. You put your accounts in a route, and each
run starts on one that still has plan quota left.

## Routing

Make a route once, then run through it:

```bash
clausona route add main                          # every Claude Code account, taking turns
clausona route explain main                      # who would be picked now, and why
clausona run --route main -- -p "run the tests"
```

The run says on stderr which account it got:

```
  ▸ claude:work  route main, next in turn, 34% of 7D used
```

By default the accounts take turns. One that has used 80% of its 5-hour or weekly limit is used
only when no other account in the route is under 80%, and then the one with the most left runs.
If every account is at 100% or can't be used (signed out, or its quota can't be read), clausona
says when each one resets or why it was skipped, and exits with code 75 instead of starting a
session.

A route is for Claude Code unless you add `--tool codex`, or `--tool all` for both tools. You can
also pick accounts by pattern, such as `*@example.com`, name fallback accounts, or choose another
strategy. `clausona route` with nothing after it opens the Routes screen, where you can create and
edit routes in a form. The dashboard has it too, under Profiles.

If agents start your runs, the `routing` plugin teaches them all of this:

```bash
claude plugin marketplace add larcane97/clausona
claude plugin install routing@clausona
```

The rest is in [docs/routing.md](https://github.com/larcane97/clausona/blob/main/docs/routing.md).

## Plugins for agent fleets

Also new since 0.5.1-beta: plugins that let one Claude Code or Codex session split a job across
parallel agents in Superset, herdr or Orca, each on its own account or API model, then check on
them and clean up after them. Install the one for the tool you use:

```bash
claude plugin marketplace add larcane97/clausona
claude plugin install superset-fleet@clausona   # or herdr-fleet, orca-fleet
```

In Codex, run `codex plugin marketplace add larcane97/clausona`, then
`codex plugin add fleet-core@clausona` and the plugin for your tool. If you installed
`clausona@clausona` before, run `claude plugin install superset-fleet@clausona` once after updating
it. Plugins come from the marketplace; `clausona update` doesn't touch them.

How it looks in each tool: [Superset](https://github.com/larcane97/clausona/blob/main/docs/usecases/superset-fleet.md),
[herdr](https://github.com/larcane97/clausona/blob/main/docs/usecases/herdr-fleet.md),
[Orca](https://github.com/larcane97/clausona/blob/main/docs/usecases/orca-fleet.md).

## Fixes

- With no account signed in, `clausona init` said to run `claude login`, even though a Codex
  account alone is enough. It now names `codex login` too.

## Updating

Choose Update on the dashboard, or run `clausona update`. Your shell hook hasn't changed, so open
shells keep working.

On 0.3.0-beta or earlier, which can't update itself, run the installer again:

```bash
curl -fsSL https://github.com/larcane97/clausona/releases/latest/download/install.sh | bash
```

```powershell
irm https://github.com/larcane97/clausona/releases/latest/download/install.ps1 | iex
```
