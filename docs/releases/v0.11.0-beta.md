This release is about the fleet plugins. There is a fourth runner, for plain tmux, and a worker's
label now follows its task when the task moves to another account. Plugin updates also reach you
again: several plugins had changed without a new version, so `claude plugin update` kept the old
copy. The `clausona` command itself hasn't changed.

## A fleet in plain tmux

The new `tmux-fleet` plugin runs a fleet with nothing but tmux, so it also works on a remote
machine over SSH. The coordinating Claude Code or Codex session opens a tmux window per task, in
its own git worktree, on its own account or API model. Each window is labelled
`<task> · <profile>`, and you can switch to any worker's window and type into it.

```bash
claude plugin marketplace update clausona
claude plugin install tmux-fleet@clausona      # fleet-core comes along
```

It needs tmux 3.2 or newer. A Claude Code worker reports through hooks that only it loads, and a
Codex worker through the terminal bell, so the coordinator knows when one is done or waiting.
[Run a tmux fleet across your accounts](https://github.com/larcane97/clausona/blob/main/docs/usecases/tmux-fleet.md)
has the setup and a walkthrough.

## Labels follow the account

Every fleet labels a worker with its task and profile, so the sidebar or status bar shows which
account runs where. When an account hit its limit and the task moved to another profile, the
label went on naming the account that stopped. Now the coordinator renames it:

- Superset renames the workspace, for example from `Paths · work (Opus 5.5)` to
  `Paths · side (Opus 5.5)`. It does the same when it gives a worker a different task.
- herdr renames the workspace, Orca the worktree, and tmux the window.

Thanks to @HyeokminFrancis for the Superset change (#188).

## Plugin updates reach you again

Claude Code updates a plugin only when its version changes. routing stayed at 0.1.0 after
0.6.0-beta, so if you installed it then, `claude plugin update` kept that copy, and its skill never
learned the 0.8.0-beta features: routes per directory, `--wait`, model limits and API budgets.
Every plugin that changed now has a new version, and a test fails when a plugin changes without
one.

## Updating

Plugins come from the marketplace, not from `clausona update`. Update the ones you use, then start
a new Claude Code session:

```bash
claude plugin marketplace update clausona
claude plugin update routing@clausona
claude plugin update superset-fleet@clausona   # or herdr-fleet, orca-fleet
claude plugin update fleet-core@clausona
```

In Codex, run `codex plugin marketplace upgrade clausona`, then `codex plugin add <plugin>@clausona`
for each plugin you use.

For the `clausona` command, choose Update on the dashboard, or run `clausona update`. Your shell
hook hasn't changed, so open shells keep working.

On 0.3.0-beta or earlier, which can't update itself, run the installer again:

```bash
curl -fsSL https://github.com/larcane97/clausona/releases/latest/download/install.sh | bash
```

```powershell
irm https://github.com/larcane97/clausona/releases/latest/download/install.ps1 | iex
```
