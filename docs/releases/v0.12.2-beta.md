This release fixes a wrong `other account` on a profile you had just added back, and tmux-fleet
workers that were refused at random on some Linux hosts.

## Fixes

- A profile you removed and added again could keep showing what clausona had read before.
  `csn list` and the dashboard keep each reading for five minutes under the profile's name, and
  removing the profile left it there. A profile added back with the right account could stay red,
  `other account`, beside the very account it was signed in to, so the re-add looked like it had
  failed. A reading with numbers could show the old account's usage under the new registration in
  the same way. Removing or adding a profile now clears its reading, and so does `clausona init`
  when it changes one. An `other account` that no longer applies is read again. (#211, #212)
- tmux-fleet could refuse a worker with `tmux opened the pane in …, not in …; nothing was started`.
  It checked a new pane's folder once, straight after opening it, and the pane may not have got
  there yet. On Ubuntu 26.04 with tmux 3.6 this happened often. It now gives the pane up to three
  seconds. A pane that really opens somewhere else is still refused. (#213, #214)

## Updating

For the `clausona` command, choose Update on the dashboard, or run `clausona update`. Your shell
hook hasn't changed, so open shells keep working.

tmux-fleet comes from the marketplace, not from `clausona update`. If you use it, update it and start
a new session:

```bash
claude plugin marketplace update clausona
claude plugin update tmux-fleet@clausona
```

In Codex, run `codex plugin marketplace upgrade clausona`, then `codex plugin add tmux-fleet@clausona`.

On 0.3.0-beta or earlier, which can't update itself, run the installer again:

```bash
curl -fsSL https://github.com/larcane97/clausona/releases/latest/download/install.sh | bash
```

```powershell
irm https://github.com/larcane97/clausona/releases/latest/download/install.ps1 | iex
```
