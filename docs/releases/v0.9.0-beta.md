An account that has to sign in again now says so on its own row in `clausona list` and on the
dashboard. A renewal that only failed this time no longer reads as a lapsed sign-in.

## A lapsed sign-in shows on its row

An account whose sign-in had lapsed used to keep its last numbers on the row, dimmed, and the one
note under the table didn't say which account it meant. Shown that way, the numbers read as
current: a Codex account signed out for a month listed `100% now`.

Now the row says it in red across the 5H and 7D columns, and the note under the table starts with
the same word:

```
PROFILE             ACCOUNT                5H         7D
claude:work         you@example.com        6% 23m     46% 13h
claude:personal     you@personal.com       signed out
codex:work          you@example.com        expired
signed out: no stored credential — run `clausona login <profile>`
expired: sign-in has lapsed — run `clausona login <profile>`
```

- `expired` means the provider refused the sign-in. The refresh token lasts about 14 days, or it
  was revoked.
- `signed out` means no credential is stored for the profile. Signing out of Claude Code leaves an
  empty one behind, and that reads this way too.

Either way, run `clausona login <profile>`. The dashboard's profile list shows the same words in
red, and the preview beside it says what to run.

API profiles and routing work as before. `clausona list --json` still has the last numbers, with
`state` set to `expired` or `missing`.
[Plan quota](https://github.com/larcane97/clausona/blob/main/docs/plan-quota.md#when-a-reading-is-unavailable)
has the details.

## Fixes

- A renewal that couldn't be tried read as `expired`, as if you had to sign in again. That
  happened when another clausona or Claude Code was renewing the same sign-in at the time, when
  you were offline, or when the token endpoint failed or was rate-limited. Now it reads as `error`
  and keeps the numbers it had. `expired` is left for a sign-in the provider refused, or one with
  no refresh token.
- `clausona repair` and `clausona doctor` said things about Codex that weren't true for a file
  Codex never wrote, such as a hand-made `config.toml.bak-*` backup that an older clausona had
  linked into a profile. They now say only what the link does.

## Updating

Choose Update on the dashboard, or run `clausona update`. Your shell hook hasn't changed, so open
shells keep working.

On 0.3.0-beta or earlier, which can't update itself, run the installer again:

```bash
curl -fsSL https://github.com/larcane97/clausona/releases/latest/download/install.sh | bash
```

```powershell
irm https://github.com/larcane97/clausona/releases/latest/download/install.ps1 | iex
```
