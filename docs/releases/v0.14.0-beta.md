This release shows `none` under 5H when a plan has no 5-hour limit. You can also install clausona from npm.

## Plans with no 5-hour limit

Verified Claude Ultra plans and some Codex plans have no 5-hour limit. `clausona list` used to show a dash under 5H for these plans, just as it does when a reading is missing. It now shows a dimmed `none` instead. A dash only appears when there is no reading.

If no account has a 5-hour limit, the 5H column is omitted:

```
PROFILE             ACCOUNT              7D
claude:team         team@example.com     34% 2d
claude:work         work@example.com     81% 1d
```

`clausona route explain` and `route show` behave the same way. So do `route add` and `route set`, along with the table on the dashboard's Routes screen. The route form puts a `5H  7D` header above its accounts. On the dashboard, the profile panel shows `Session  no 5-hour limit`.

In `clausona list --json`, each profile's `quota` object includes a new `sessionLimit` field. It is `true` when the plan has a 5-hour limit and `false` when it does not. When the reading doesn't say, as for an API profile, it is `null`. Each member in `clausona route explain --json` has the same field. Nothing else in the JSON output changed.

Routing selects the same accounts as before. Accounts without a 5-hour limit are ranked by their 7D alone.

A bare `--wait` still waits up to 5 hours. On a plan with only a weekly limit, the next reset is often days away, so the command exits 75 right away. The message gives the `--wait` value needed to reach that reset, such as `--wait=52h`. The help text for `run` and `route pick` now explains this.

If a reading cannot be refreshed, clausona no longer keeps a window whose reset time has passed. Previously, an expired window kept showing its old usage as if it were current. (#221)

## Installing from npm

clausona is now available on npm:

```bash
npm install -g clausona
```

Because npm does not edit your shell profile, you need to add the shell hook yourself and open a new shell. On zsh or bash, add this line to `~/.zshrc` or `~/.bashrc`:

```bash
eval "$(clausona shell-init)"
```

On PowerShell, add this line to the file at `$PROFILE.CurrentUserAllHosts`:

```powershell
Invoke-Expression (& clausona shell-init | Out-String)
```

If you install with npm, you also update with npm. Both `clausona update` and the dashboard tell you to run `npm install -g clausona@latest`, as does the question shown after commands. To remove it, run `clausona uninstall` first and then `npm uninstall -g clausona`.

The npm package contains the same `clausona.js` file as the GitHub release, with no dependencies and no install scripts. If you already installed clausona with the install script, keep that setup. Installing from npm as well will put a second copy on your PATH. (#220)

## Plugins

The `routing` plugin, along with `fleet-core` and `superset-fleet`, now supports plans with no 5-hour limit. Agents read `sessionLimit` and rank those accounts by their 7D. Because plugins come from the marketplace rather than `clausona update`, update them there:

```bash
claude plugin marketplace update clausona
claude plugin update routing@clausona
```

If you use `fleet-core@clausona` or `superset-fleet@clausona`, update them the same way. In Codex, run `codex plugin marketplace upgrade clausona`. (#222)

## Updating

To update the `clausona` command, choose Update on the dashboard or run `clausona update`. Your shell hook has not changed, so open shells keep working.

Versions 0.3.0-beta and earlier cannot update themselves. Run the installer again instead:

```bash
curl -fsSL https://github.com/larcane97/clausona/releases/latest/download/install.sh | bash
```

```powershell
irm https://github.com/larcane97/clausona/releases/latest/download/install.ps1 | iex
```
