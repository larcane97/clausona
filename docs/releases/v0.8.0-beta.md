Routing no longer needs `--route` every time, can wait for an account instead of giving up,
counts a model's own limit, and can take an API profile once it has a budget. The Extensions
screen reads more of what Claude Code and Codex actually load, and its changes are safer.

## A route for each directory, and a default

Tell clausona which route a directory uses, and which one to use everywhere else:

```bash
clausona route dir ~/work work        # in ~/work and below, clausona run claude uses route work
clausona route default main           # everywhere else, route main
clausona route explain                # what claude and codex would each do here, and why
```

Then `clausona run claude` picks by quota on its own, and says which rule it followed:

```
  ▸ claude:b  route work (dir rule ~/work), next in turn, 40% of 7D used
```

The deepest rule that holds for the current directory wins, then the default, then the active
profile. A rule that names a route that doesn't exist is skipped with a one-line warning, and
`route rename` and `route remove` carry the rules along. On the Routes screen, `tab` switches to
the dir rules.

## Waiting for an account

When every account in a route is used up, a run used to stop with exit code 75. With `--wait` it
waits for the first one to free up instead, for up to 5 hours or the cap you give:

```bash
clausona run --route main --wait=2h -- -p "run the tests"
clausona route pick main --wait --json      # for a script or an orchestrator taking its turn
```

It says what it is waiting for, `waiting until 14:05 for claude:work (5H resets) …`, keeps going
through a failed quota read, and Ctrl-C stops it. Past the cap it still exits 75, and the message
now names the `--wait` that would have reached the next reset.

## A model's own limit

Some plans limit a model on its own, like Opus on Claude Code or Spark on Codex. When a run names
the model, routing now counts that limit too:

```bash
clausona run --route main -- --model opus -p "…"
clausona route explain main --model opus
```

An account whose Opus week is used up is skipped even if its overall limits are fine. A run that
names no model counts no model limit. For Codex, both the 5-hour and the weekly window of a model
limit are read, and the higher one counts. On the Routes screen, `m` ranks the selected route as
a run of one model, so you can see which account an Opus run would get.

## API profiles in routes

An API profile can now join a route once it has a spend limit. Give it a budget, then add it by
name:

```bash
clausona route budget claude:gateway --usd 20 --per month
clausona route set main --add claude:gateway
```

The run note says what it is: `API, billed per use · usage 35% of $20/month`. Spend is read from
OpenRouter, or from a LiteLLM proxy's `/key/info`; a proxy that doesn't offer it reads as "the
provider does not report spend", and the profile stays out of routes. Without a budget, the limit
set on the provider key counts. A budget stops new routed sessions, not one already running.
`clausona route budget` lists every API profile with its limit and spend, and `b` on the Routes
screen does the same.

All of this is in [docs/routing.md](https://github.com/larcane97/clausona/blob/main/docs/routing.md).

## Fixes in routing

- A mistake in one route in `routes.json` used to stop every route, and even
  `clausona run claude`. Now only that route is refused, and `route list` shows what is wrong
  with it.
- A long prompt typed where the profile goes was called an API key. It now gets the hint to name
  the tool first.
- An account at 79.6% of an 80% cut showed as 80%, next to another marked over the cut. It now
  shows 79%, and an account at 100% reads `at 100%`.
- When `routes.json` changed while `clausona route edit` was open, your edit was thrown away. It
  is now kept in `~/.clausona/routes.edit.json`.
- The route form flickered in terminals narrower than about 77 columns, and dropped keys typed
  very fast. Both are fixed.
- `route list --json` now says which account is free and next, and with `--json` a failure prints
  JSON too.
- On macOS and Linux, a `command:` key source that leaves a job running in the background no
  longer makes the spend read wait out its 5 seconds and fail. The job is stopped when the command
  exits, while an agent that runs in a session of its own (gpg-agent, ssh-agent) is left running.
- A key command's background job no longer holds up a launch or `clausona doctor` either: the key
  is read as soon as the command exits. A command that asks for a PIN or passphrase on the
  terminal works as before.
- `clausona doctor` and the Health check screen now give a key command 60 seconds instead of
  waiting on it for good, then stop it the way Ctrl-C would.
- A LiteLLM key with a `budget_duration` but no `max_budget` now has its provider resets counted,
  so spend before a reset still counts toward a clausona budget. Editing a key in LiteLLM is, in
  most cases, no longer taken for a reset.
- On the Routes screen, moving from one model to the next with `m` no longer switches the table
  between gauges and percentages. The view with no model looks as before.

## Extensions: closer to what loads

The Extensions screen and `clausona skills|mcp|hooks` now read more of what turns things on and
off, so a row reads `on` only when Claude Code or Codex would start it:

- Claude settings that switch a whole kind off: `disableAllHooks`, `disableBundledSkills`, and
  your organization's `managed-mcp.json`, `allowedMcpServers` and `deniedMcpServers`, with
  `${VAR}` in them read the way Claude Code reads it.
- Codex plugins, under their own Plugins scope, with the skills, servers and hooks they bring,
  and a warning when Codex drops a plugin's inline hooks because one of them is bad.
- Codex skills as Codex names and skips them. A skill Codex won't load says why:
  `no front matter`, `no description`, `invalid front matter` or `name too long`. The front
  matter check follows YAML tags, anchors, `?` keys and document markers the way Codex reads them.
- A Codex `config.toml` or hooks file that Codex itself won't read, such as a wrong type in its
  servers, skills, hooks, plugins or projects, or a hook `timeout` written `30.0`. Where Codex
  refuses a trusted project's `config.toml`, nothing of Codex loads in that project, your own config
  included, and the list says so. Where it refuses `~/.codex/config.toml`, every Codex row reads
  off.
- Codex hooks on an event Codex doesn't know, or with a matcher Codex can't compile, read
  `unknown event` or `invalid matcher` instead of `on`.
- A trusted project's Codex server shows what Codex runs: the project's settings over yours.
- Codex hooks Codex hasn't trusted yet read `pending approval`. A project Codex doesn't trust
  shows its own servers and hooks as off, and a worktree or a folder inside a trusted repo counts
  as trusted, as it does in Codex. In a linked worktree, the list shows the main checkout's hooks,
  the ones Codex runs there.
- A `.mcp.json` in a folder above your home folder, and the servers and hooks a plugin names by
  path in its `plugin.json`.

On Claude's MCP tab, `m` opens the matrix of servers by account. You can now press `space` on a
cell to turn that one account's server off or on in this project, and `u` to undo it.

## Extensions: safer changes

- `rm` says when deleting a folder breaks skill links that point into it, such as a gstack folder
  and its 30 links.
- A change that would do nothing is refused with the reason, such as a server a deny list keeps
  off, a hook under `disableAllHooks`, or `hooks on` for a Codex hook Codex skips.
- Approving a `.mcp.json` server shows what it runs before it is approved, and `space` on a
  pending server approves it.
- When clausona creates a project's `.claude/settings.local.json`, it adds Claude Code's line to
  your global git ignore, as Claude Code does, so the file isn't committed by mistake.
- If git or `ps` doesn't answer in time, clausona no longer takes that as "not tracked" or "Codex
  isn't running": it asks for `--tracked` or `--force` instead.
- More secret shapes are hidden in commands shown on screen and in `--json`, checked against the
  old rules over hundreds of thousands of command shapes so that nothing hidden before shows now.

## Fixes in Extensions

- An account whose skills folder isn't linked to your main account's showed your Global skills as
  loading there. It no longer does, and its Cloud skills are its own.
- Two projects with the same folder name, like `work/app` and `personal/app`, read the same
  everywhere. They now read apart.
- A delete cut short while moving to a backup on another drive could leave a second copy of the
  skill where Claude Code loads it. The next change or `undo` now finishes or rolls back the move.
- A Codex `[projects."…"]` key written with a trailing slash or a `..` read as trusted, though Codex
  doesn't trust it. It now matches only as Codex does: the exact path, and on Windows ignoring
  only ASCII case.

## Updating

Choose Update on the dashboard, or run `clausona update`. Your shell hook hasn't changed, so open
shells keep working.

The `routing` plugin's skill for agents changed too. Plugins come from the marketplace, not
`clausona update`, so update it there (in Codex, `codex plugin marketplace upgrade clausona`):

```bash
claude plugin marketplace update clausona
claude plugin update routing@clausona
```

On 0.3.0-beta or earlier, which can't update itself, run the installer again:

```bash
curl -fsSL https://github.com/larcane97/clausona/releases/latest/download/install.sh | bash
```

```powershell
irm https://github.com/larcane97/clausona/releases/latest/download/install.ps1 | iex
```
